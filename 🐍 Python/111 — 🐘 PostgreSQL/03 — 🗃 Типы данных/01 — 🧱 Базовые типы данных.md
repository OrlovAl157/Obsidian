# 🧱 Базовые типы данных — памятка

> PostgreSQL имеет богатую систему типов. Ключевые отличия от MySQL: `TEXT` без ограничения длины, `BOOLEAN` как полноценный тип, `NUMERIC` для точных чисел, `SERIAL`/`BIGSERIAL` для автоинкремента.

## Справка

| Тип | Описание | Пример |
|---|---|---|
| `SMALLINT` | целое -32768..32767 | возраст |
| `INTEGER` / `INT` | целое -2.1млрд..2.1млрд | id |
| `BIGINT` | большое целое | id в огромных таблицах |
| `NUMERIC(p,s)` | точное число | деньги, вес |
| `REAL` | float 4 байта | координаты |
| `DOUBLE PRECISION` | float 8 байт | научные вычисления |
| `CHAR(n)` | строка фиксированной длины | код страны |
| `VARCHAR(n)` | строка до n символов | имя |
| `TEXT` | строка без ограничения | описание |
| `BOOLEAN` | true / false | активен? |
| `DATE` | дата | день рождения |
| `TIME` | время | время события |
| `TIMESTAMP` | дата + время | момент создания |
| `TIMESTAMPTZ` | дата + время + часовой пояс | рекомендуется! |
| `INTERVAL` | интервал | длительность |
| `UUID` | уникальный идентификатор | внешние id |
| `SERIAL` | автоинкремент INT | pk небольшой таблицы |
| `BIGSERIAL` | автоинкремент BIGINT | pk большой таблицы |

## 🔢 Числовые типы

```sql
-- Целые
age      SMALLINT           -- -32768 до 32767
id       INTEGER            -- -2.1 млрд до 2.1 млрд
big_id   BIGINT             -- очень большие числа

-- Точные (не теряют точность — для денег!)
price    NUMERIC(10, 2)     -- до 10 цифр, 2 после запятой
weight   DECIMAL(8, 3)      -- DECIMAL = NUMERIC

-- Приблизительные (могут терять точность)
ratio    REAL               -- ~7 значимых цифр
value    DOUBLE PRECISION   -- ~15 значимых цифр
```

**Для денег всегда `NUMERIC`, а не `FLOAT`/`REAL`** — числа с плавающей точкой дают погрешность при арифметике.

---

## 🔤 Строковые типы

```sql
code     CHAR(2)            -- ровно 2 символа (дополняется пробелами)
name     VARCHAR(100)       -- до 100 символов
bio      TEXT               -- без ограничения длины
```

**В PostgreSQL `TEXT` и `VARCHAR` без ограничения — одинаковы по производительности.** Используй `TEXT` для длинных строк, `VARCHAR(n)` только если хочешь явно ограничить длину.

## 📅 Дата и время

```sql
birth_date  DATE               -- '2025-10-16'
event_time  TIME               -- '14:30:00'
created_at  TIMESTAMP          -- '2025-10-16 14:30:00' (без часового пояса)
updated_at  TIMESTAMPTZ        -- '2025-10-16 14:30:00+03' (с часовым поясом)
duration    INTERVAL           -- '2 hours 30 minutes'
```

**Рекомендуется хранить `TIMESTAMPTZ`, а не `TIMESTAMP`** — PostgreSQL автоматически переводит в UTC при хранении и в локальное время при чтении.

## ✅ Логический тип

```sql
is_active  BOOLEAN DEFAULT TRUE

-- Допустимые значения при вставке
INSERT INTO Users (is_active) VALUES (TRUE);
INSERT INTO Users (is_active) VALUES (FALSE);
INSERT INTO Users (is_active) VALUES ('yes');   -- тоже работает
INSERT INTO Users (is_active) VALUES ('no');    -- тоже работает
INSERT INTO Users (is_active) VALUES (1);       -- тоже работает

-- Фильтрация
SELECT * FROM Users WHERE is_active;             -- WHERE is_active = TRUE
SELECT * FROM Users WHERE NOT is_active;         -- WHERE is_active = FALSE
```

## 🆔 Автоинкремент

```sql
-- SERIAL — короткий синтаксис (устаревает)
id SERIAL PRIMARY KEY        -- INTEGER + SEQUENCE
id BIGSERIAL PRIMARY KEY     -- BIGINT + SEQUENCE

-- GENERATED AS IDENTITY — современный стандарт SQL (рекомендуется)
id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

---

## ✅ Главные правила

✅ Деньги → `NUMERIC(p,s)`, не `FLOAT`  
✅ Длинные строки → `TEXT`, не `VARCHAR` без нужды  
✅ Временные метки → `TIMESTAMPTZ`, не `TIMESTAMP`  
✅ Автоинкремент → `GENERATED AS IDENTITY` (современно) или `SERIAL` (классика)  
✅ Нет `TINYINT`, `DATETIME` (MySQL) → `SMALLINT`, `TIMESTAMP` в PostgreSQL
