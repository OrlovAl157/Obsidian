# 📐 Схемы — памятка

> Схема (schema) — пространство имён внутри базы данных. Позволяет организовывать объекты (таблицы, функции, представления) по логическим группам. По умолчанию используется схема `public`.

## Справка

| Синтаксис | Что делает |
|---|---|
| `CREATE SCHEMA name` | создать схему |
| `DROP SCHEMA name` | удалить схему |
| `DROP SCHEMA name CASCADE` | удалить со всем содержимым |
| `schema.table` | обратиться к объекту схемы |
| `SET search_path TO schema` | установить схему по умолчанию |
| `\dn` | список схем (psql) |

---

## 🟢 Создание и удаление

```sql
CREATE SCHEMA analytics;
CREATE SCHEMA IF NOT EXISTS analytics;

-- Удалить пустую схему
DROP SCHEMA analytics;
-- Удалить со всем содержимым
DROP SCHEMA analytics CASCADE;
```

---

## 🔵 Работа со схемами

```sql
-- Создать таблицу в схеме
CREATE TABLE analytics.reports (
    id      SERIAL PRIMARY KEY,
    name    TEXT,
    created TIMESTAMP DEFAULT NOW()
);

-- Обратиться к таблице
SELECT * FROM analytics.reports;

-- Переместить таблицу в другую схему
ALTER TABLE public.reports SET SCHEMA analytics;
```

---

## 🔴 search_path

```sql
-- Текущий search_path
SHOW search_path;

-- Установить схему по умолчанию для сессии
SET search_path TO analytics, public;

-- После этого можно не писать схему явно:
SELECT * FROM reports;   -- ищет в analytics, потом в public
```

---

## ✅ Главные правила

✅ Схема `public` — по умолчанию, видна без префикса  
✅ `schema.table` — явное указание схемы  
✅ `search_path` — порядок поиска объектов по схемам  
✅ `DROP SCHEMA CASCADE` — удаляет все объекты внутри
