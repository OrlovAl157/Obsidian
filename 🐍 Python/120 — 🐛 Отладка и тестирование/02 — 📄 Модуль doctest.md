# 📄 Модуль doctest

## 📌 Коротко

> `doctest` — встроенный фреймворк, который извлекает тестовые случаи прямо из строк документации (docstring), имитируя интерактивную сессию Python. Хорош для простых примеров, встроенных в документацию функции.

---

## 🚀 Быстрая справка

| Действие | Как |
|---|---|
| Записать тест в docstring | `>>> вызов()` на одной строке, ожидаемый результат — на следующей |
| Запустить тесты | `doctest.testmod()` |
| Запустить через pytest | `pytest --doctest-modules` |
| Проверить строки | ожидаемый результат = `repr()` объекта, а не `str()` |

---

## 📖 Основное

### Базовое использование

В docstring имитируется интерактивная сессия: строка вызова с `>>>`, затем строка ожидаемого результата.

```python
def factorial(n):
    """
    >>> factorial(0)
    1
    >>> factorial(7)
    5040
    """
    if not isinstance(n, int) or n < 0:
        raise ValueError('Некорректный аргумент.')
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result


if __name__ == '__main__':
    import doctest
    doctest.testmod()
```

Если фактический результат не совпадает с ожидаемым — `testmod()` выводит подробный отчёт: файл, строку, вызов, ожидаемое и фактическое значение. Если всё совпало — вывода нет вообще.

Строку документации можно совмещать с обычным текстом — интерактивные блоки просто перемежаются с описанием:

```python
def factorial(n):
    """
    Функция возвращает факториал числа.
    >>> factorial(0)
    1
    """
```

### Тестирование исключений

После вызова с некорректным аргументом указывается сокращённая трассировка — `Traceback` + `...` + строка с типом и текстом исключения:

```python
def factorial(n):
    """
    >>> factorial(-1)
    Traceback (most recent call last):
    ...
    ValueError: Некорректный аргумент.
    """
```

Содержимое многоточия неважно — doctest сравнивает только последнюю строку с текстом исключения. Она должна совпасть **дословно**.

### ⚠️ Частые ловушки

**1. Ожидаемый результат — это `repr()`, а не `print()`.** Для строк нужно писать значение в кавычках, иначе тест провалится, даже если функция работает правильно:

```python
def return_string(s):
    """
    >>> return_string('beegeek')
    'beegeek'
    """
    return s
```

Если написать `beegeek` без кавычек — тест не пройдёт, хотя функция верна.

**2. Комментарии нельзя оставлять в строке с ожидаемым значением** — они станут частью ожидаемого текста. Комментарий можно писать только в строке вызова:

```python
"""
>>> factorial(0)  # факториал нуля — правильно, комментарий в строке вызова
1
"""
```

**3. Если в docstring нет ни одной строки `>>>` — `testmod()` просто ничего не найдёт, ошибки при этом не будет.**

### Списки тестовых случаев

Можно имитировать целую последовательность вызовов, а не расписывать каждый отдельно:

```python
def factorial(n):
    """
    >>> test_cases = [0, 1, 2, 3, 7]
    >>> [factorial(num) for num in test_cases]
    [1, 1, 2, 6, 5040]
    """
```

## 💡 Важные нюансы

- doctest удобен для простых примеров использования, но неудобен для сложных сценариев (много подготовки данных, mock-объекты) — для этого лучше unittest/pytest.
- Строка документации выполняет двойную роль: и документация, и тест. Если тест не пройден, автоматически становится ясно, что и сама документация устарела.
- Тесты в doctest легко запускать вместе с pytest через `--doctest-modules`, не переписывая их отдельно.
