# 🧩 unittest — основы

## 📌 Коротко

> `unittest` — встроенный фреймворк для модульного тестирования (по образцу Java JUnit). Тесты оформляются как методы классов-наследников `unittest.TestCase`, каждый метод — независимый автономный тест.

---

## 🚀 Быстрая справка

| Правило | Требование |
|---|---|
| Имя тестового метода | обязан начинаться с `test` |
| Имя тестового класса | наследник `TestCase`, желательно с префиксом `Test` |
| Проверка внутри метода | минимум один вызов `self.assert...()` |
| Запуск всех тестов | `unittest.main()` |
| Подробность отчёта | `unittest.main(verbosity=0/1/2)` |

---

## 📖 Основное

### Минимальный пример

```python
import unittest


class TestSum(unittest.TestCase):
    def test_list_positive_integers(self):
        self.assertEqual(sum([1, 2, 3]), 6)

    def test_list_negative_integers(self):
        self.assertEqual(sum([-1, -2, -3]), -6)


if __name__ == '__main__':
    unittest.main()
```

Вывод при успехе:

```
..
----------------------------------------------------------------------
Ran 2 tests in 0.000s

OK
```

Точка — успешный тест, `F` — проваленный. Если метод не содержит ни одного `assert...()`, он всё равно засчитывается успешным (исключений не было) — но такой тест бесполезен.

### Параметр verbosity

Управляет подробностью отчёта у `unittest.main()`:

| Значение | Поведение |
|---|---|
| `0` | только итог (`Ran N tests`, `OK`/`FAILED`) |
| `1` (по умолчанию) | строка из точек/F |
| `2` | каждый тест по отдельности + `ok`/`FAIL`, докстринг метода (если есть) выводится как описание теста |

Тесты выполняются не в порядке объявления в коде, а **в лексикографическом порядке имён методов**. Если нужен конкретный порядок — добавляют номер в имя: `test_01_...`, `test_02_...`.

### Отчёт о проваленных тестах

```
F
======================================================================
FAIL: test_list_positive_integers (__main__.TestSum.test_list_positive_integers)
----------------------------------------------------------------------
Traceback (most recent call last):
  File "main.py", line 6, in test_list_positive_integers
    self.assertEqual(sum([1, 2, 3]), 5)
AssertionError: 6 != 5

----------------------------------------------------------------------
Ran 1 test in 0.001s

FAILED (failures=1)
```

Итог `FAILED (failures=N)` вместо `OK` — общее число проваленных тестов. Полная трассировка `AssertionError` показывает, что ожидалось и что получено на самом деле.

### Файлы с тестами

Обычно тесты выносят в отдельные файлы с префиксом `test_` или суффиксом `_test` (для совместимости и с unittest, и с pytest).

---

## 💡 Важные нюансы

- unittest использует объектно-ориентированный подход — в этом его отличие от pytest, который тяготеет к функциональному стилю.
- Тестовый метод без `assert...()` не выдаёт ошибку компиляции, но и не имеет практического смысла — легко забыть и решить, что тест "работает".
- Порядок выполнения тестов — лексикографический, не по порядку в файле; это важно учитывать при работе с общим состоянием (см. фикстуры).
