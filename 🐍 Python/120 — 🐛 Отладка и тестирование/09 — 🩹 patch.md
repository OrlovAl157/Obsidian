# 🩹 patch

## 📌 Коротко

> `patch` — декоратор/контекстный менеджер из `unittest.mock`, который временно заменяет реальный объект на мок (`MagicMock`) внутри указанной области кода, а после выхода из неё возвращает всё как было. Это основной способ подключения моков в реальных тестах.

---

## 🚀 Быстрая справка

| Способ | Синтаксис | Где действует замена |
|---|---|---|
| Декоратор | `@patch('модуль.объект')` | внутри всей функции/метода, доп. параметр обязателен |
| Контекстный менеджер | `with patch('модуль.объект') as mock:` | только внутри `with`-блока |
| Точечная замена | `patch.object(Класс, 'метод')` | без указания полного пути строкой |
| Несколько объектов | `patch.multiple(объект, a=Mock(), b=Mock())` | несколько замен одним вызовом |

---

## 📖 Основное

### Декоратор @patch

Указывается **полный путь** к объекту, начиная с модуля, где он определён:

```python
from unittest.mock import patch

@patch('__main__.max')          # встроенные функции — модуль __main__
def test(mock_max):             # доп. параметр — тот же мок, что подменил max
    print(max)                  # <MagicMock name='max' ...>
    print(mock_max)             # тот же объект

test()
print(max)                      # снаружи — обычная встроенная функция, без изменений
```

Имя параметра (`mock_max`) можно выбрать любое — оно не связано магически с именем объекта, просто через него удобно ссылаться на мок внутри функции без повторения полного пути.

### Контекстный менеджер patch

Когда нужно подменить объект только на части функции, а не целиком:

```python
def test():
    print(max([1, 2, 3]))          # 3 — реальная функция

    with patch('__main__.max') as mock_max:
        find_max([1, 2, 3])
        print(mock_max.called)     # True

    print(max([1, 2, 3]))          # 3 — снова реальная функция
```

При использовании как контекстного менеджера доп. параметр в сигнатуре функции не нужен — переменная создаётся через `as`.

### Практические примеры

**Подмена времени** — избегаем зависимости теста от даты запуска:

```python
class TestIsWeekend(unittest.TestCase):
    @patch('datetime.datetime')
    def test_is_weekend(self, mock_datetime):
        mock_datetime.now.return_value = datetime.date(2025, 7, 20)   # воскресенье
        self.assertTrue(is_weekend())
```

**Подмена побочного эффекта** (удаление файла) — проверяем сам факт вызова, не выполняя реальное удаление:

```python
class TestRm(unittest.TestCase):
    @patch('os.remove')
    def test_is_remove(self, mock_remove):
        rm('file1.txt')
        mock_remove.assert_called_with('file1.txt')
```

**Имитация исключения** — сеть недоступна:

```python
@patch('requests.get', side_effect=Timeout)   # side_effect можно задать прямо в декораторе
def test_timeout(self, mock_get):
    with self.assertRaises(Timeout):
        get('https://example.com')
```

### patch.object — без строкового пути

Когда объект уже импортирован и доступен напрямую, вместо строки с полным путём можно передать сам объект:

```python
with patch.object(Cat, 'say'):
    print(cat.say())   # <MagicMock ...>
```

---

## 💡 Важные нюансы

- Декоратор `@patch` на классе применяет замену **ко всем тестовым методам** класса — но не к `setUp`/`tearDown` (там объект остаётся настоящим).
- Встроенные неизменяемые типы (`datetime.datetime`, `float` и т.п.) нельзя патчить по отдельному атрибуту — замене подлежит только весь объект целиком.
- Несколько декораторов `@patch` на одной функции — параметры получают моки **снизу вверх** (в порядке применения декораторов).
- Для функции `open()` лучше использовать специальную `mock_open()` — она корректно поддерживает и обычный вызов, и `with open(...) as f`.
