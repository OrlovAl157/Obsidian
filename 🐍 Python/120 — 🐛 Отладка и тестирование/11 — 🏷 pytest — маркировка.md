# 🏷 pytest — маркировка и параметризация

## 📌 Коротко

> Маркеры (`@pytest.mark...`) — декораторы, позволяющие категоризировать тесты, выборочно запускать их подмножества и создавать несколько вариантов теста из одного набора данных. Ключевые встроенные маркеры: `parametrize`, `skip`, `skipif`, `xfail`.

---

## 🚀 Быстрая справка

| Маркер | Назначение |
|---|---|
| `@pytest.mark.parametrize('args', [...])` | несколько вариантов теста с разными данными |
| `@pytest.mark.skip(reason)` | безусловный пропуск |
| `@pytest.mark.skipif(condition, reason=...)` | условный пропуск |
| `@pytest.mark.xfail(reason=...)` | тест ожидаемо провалится |
| `@pytest.mark.<своё_имя>` | пользовательский маркер (нужна регистрация в `pytest.ini`) |
| `pytest -m <имя>` | запустить только тесты с этим маркером |
| `pytest -m 'not <имя>'` | запустить все, кроме отмеченных |

---

## 📖 Основное

### parametrize — компактная замена subTest()

То, что в unittest требует `subTest()` внутри цикла, в pytest выражается одним декоратором:

```python
@pytest.mark.parametrize('n, expected', [(1, 1), (5, 120), (10, 3628800)])
def test_normal_case(n, expected):
    assert factorial(n) == expected
```

Каждый кортеж из списка — отдельный, независимый запуск теста с этими значениями аргументов. Первый аргумент — строка с именами параметров через запятую (или список строк), второй — список кортежей со значениями.

**Ловушка с одним аргументом:** если аргумент один, элементы списка — это сами значения, а не кортежи из одного элемента:

```python
@pytest.mark.parametrize('n', [1])      # n = 1 (число)     ✅
@pytest.mark.parametrize('n', [(1,)])   # n = (1,) (кортеж)  ❌ скорее всего не то, что нужно
```

### Пользовательские маркеры

Своё имя маркера нужно зарегистрировать в `pytest.ini`, иначе будет предупреждение о «неизвестном» маркере:

```ini
[pytest]
markers =
    normal_case
```

```python
class TestFactorial:
    @pytest.mark.normal_case
    def test_factorial_one(self):
        assert factorial(1) == 1
```

Запуск только помеченных тестов: `pytest -m normal_case`. Маркеры можно комбинировать с именованными аргументами для более точной фильтрации: `@pytest.mark.normal_case(id=1)` → `pytest -m 'normal_case(id=1)'`.

### skip / skipif

Аналоги `@unittest.skip`/`@skipIf`, но нет отдельного аналога `skipUnless` — вместо него `skipif` с `not`:

```python
@pytest.mark.skip('Функционал ещё не реализован.')
def test_incorrect_argument(self): ...

@pytest.mark.skipif(sys.version_info[:2] < (3, 12), reason='Нужен Python 3.12+.')
def test_batched(self): ...

@pytest.mark.skipif(not sys.platform.startswith('win'), reason='Требуется ОС Windows.')
def test_os_windows(self): ...
```

`reason` в `skipif` обязателен только по имени — без него будет `ERROR`.

### xfail — ожидаемо ошибочный тест

Помечает тест как заведомо проваленный (баг известен, ждёт исправления) — при провале в отчёте будет `XFAIL`, а не `FAILED`:

```python
@pytest.mark.xfail(reason='Ошибка будет исправлена позже.')
def test_example(self):
    assert False
```

Параметр `strict=True` переворачивает логику: если такой тест **неожиданно пройдёт**, это тоже будет засчитано как провал (`XPASS(strict)`) — сигнал, что баг уже исправлен и маркер пора снять.

---

## 💡 Важные нюансы

- `parametrize` — самый частый способ сократить дублирование в pytest, заменяет и ручные циклы, и `subTest()`.
- Без регистрации в `pytest.ini` собственные маркеры всё равно работают, но pytest выдаёт предупреждение о неизвестном маркере.
- `xfail` — не то же самое, что `skip`: `xfail` **выполняет** тест и проверяет, что он действительно упал, `skip` — не выполняет вовсе.
