# 🎭 Mock — основы

## 📌 Коротко

> Mock-объекты имитируют реальные объекты Python в тестах — позволяют управлять их поведением (что вернуть, какое исключение возбудить) и отслеживать вызовы, не выполняя реальную логику (обращение к БД, сети, текущему времени и т.п.). Создаются классом `Mock` из `unittest.mock`.

---

## 🚀 Быстрая справка

| Инструмент | Назначение |
|---|---|
| `Mock()` | базовый мок-объект, имитирует любые атрибуты/методы |
| `mock.return_value` | что вернуть при вызове мока |
| `mock.side_effect` | функция / исключение / итерируемый объект — управляет побочным эффектом вызова |
| `Mock(name='...')` | задать имя для читаемого вывода |

---

## 📖 Основное

### Зачем нужны моки

Проблема: функция `is_weekend()` зависит от `datetime.now()` — результат её теста меняется в зависимости от дня недели, когда тест запускают. Такую функцию нельзя протестировать однозначно без подмены реального времени. Мок решает это — подменяет `datetime.now()` на объект с заранее известным поведением.

### Создание и точечная нотация

Мок имитирует произвольные атрибуты и методы любой вложенности — даже если их нет у реального объекта:

```python
from unittest.mock import Mock

mock = Mock()
mock.a.b.c            # <Mock name='mock.a.b.c' ...> — создаётся "на лету"
mock.get().max()      # тоже сработает, хотя get()/max() нигде не определены
```

Чтобы вывод мока был читаемым, указывают имя:

```python
datetime = Mock(name='datetime')
```

### return_value — что вернуть при вызове

По умолчанию вызов мока возвращает другой мок. Это значение можно заменить:

```python
from datetime import datetime
from unittest.mock import Mock

dt = datetime(2025, 7, 15)
datetime = Mock(name='datetime')
datetime.now.return_value = dt

print(datetime.now())   # 2025-07-15 00:00:00 — теперь всегда одно и то же
```

Так функция `is_weekend()`, использующая `datetime.now()`, начинает давать предсказуемый, воспроизводимый результат в тесте.

### side_effect — управление побочным эффектом

Принимает три разных вида значений:

**1. Вызываемый объект** — вызывается при каждом обращении к моку, его результат становится результатом мока (имеет приоритет над `return_value`):

```python
def side_effect(a, b):
    return a + b

mock = Mock()
mock.side_effect = side_effect
mock(1, 2)   # 3 — вызвана функция side_effect
```

**2. Тип или объект исключения** — при каждом вызове мока возбуждается это исключение:

```python
mock.side_effect = ValueError('Ошибка')
mock()   # ValueError: Ошибка
```

Полезно для имитации ситуаций «сервер иногда недоступен», «файл иногда отсутствует» и т.п.

**3. Итерируемый объект** — при каждом вызове возвращается очередной элемент; после исчерпания — `StopIteration`:

```python
dates = [datetime(2025, 7, 15), datetime(2025, 7, 16)]
datetime.now.side_effect = dates

datetime.now()   # 2025-07-15
datetime.now()   # 2025-07-16
datetime.now()   # StopIteration
```

Если среди элементов есть исключение — оно будет возбуждено на соответствующем вызове.

---

## 💡 Важные нюансы

- `side_effect` имеет приоритет над `return_value` — если задано и то, и другое, вызывается `side_effect`.
- Оба атрибута можно задать сразу при создании: `Mock(return_value=..., side_effect=...)`.
- Мок можно настроить сразу через `configure_mock(**{'now.return_value': dt})` — удобно для нескольких настроек одним вызовом.
- Для ограничения интерфейса мока (доступны только реальные атрибуты объекта) используется `Mock(spec=КлассОригинала)`.
