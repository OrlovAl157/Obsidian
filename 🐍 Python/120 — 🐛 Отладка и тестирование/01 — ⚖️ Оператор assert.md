# ⚖️ Оператор assert

## 📌 Коротко

> `assert` — встроенный оператор для проверки истинности утверждения. Используется для самопроверок и отладки: если условие ложно, возбуждается `AssertionError`. Не предназначен для проверки пользовательского ввода, так как может быть отключён.

---

## 🚀 Быстрая справка

| Форма | Синтаксис | Поведение |
|---|---|---|
| Базовая | `assert условие` | ошибка `AssertionError` без сообщения, если условие ложно |
| С сообщением | `assert условие, 'текст'` | ошибка `AssertionError: текст` |
| Эквивалент | `if not условие: raise AssertionError('текст')` | то же самое вручную |

---

## 📖 Основное

### Как используется в тестировании

`assert` позволяет проверить как аргументы функции, так и промежуточные и итоговые результаты вычислений — прямо внутри тестируемой функции или в отдельном скрипте с тестовыми данными.

```python
def factorial(n):
    assert isinstance(n, int) and n >= 0, 'Некорректный аргумент'

    result = 1
    assert result == 1, 'Неверное промежуточное значение'  # проверка инварианта

    for i in range(1, n + 1):
        result *= i
    return result

test_cases = [(0, 1), (1, 1), (2, 2), (3, 6), (7, 5040)]

for n, expected in test_cases:
    result = factorial(n)
    assert result == expected, f'Ожидаемо: {expected}, получено: {result}'

print('Все тесты выполнены успешно.')
```

Если хотя бы один тест провален — выполнение прервётся на первом же несовпадении с трассировкой `AssertionError`.

### Частая ошибка — скобки

`assert` — это **оператор**, а не функция. `assert(условие, 'сообщение')` создаёт непустой кортеж `(условие, 'сообщение')`, который всегда truthy — проверка перестаёт работать.

```python
assert(2 + 2 == 5, 'Ошибка')   # ❌ не сработает — кортеж всегда True
assert 2 + 2 == 5, 'Ошибка'    # ✅ правильно
```

### Отключение assert

Все `assert` можно отключить флагом интерпретатора `-O` (оптимизация) — тогда они просто не выполняются:

```bash
python -O script.py
```

**Отсюда главное правило:** код должен корректно работать и без assert. Поэтому `assert` нельзя использовать для валидации данных, которые обязательно нужно проверить (например, ввод пользователя) — для этого нужны обычные исключения (`raise ValueError`, `raise TypeError`).

### Ограничение — нельзя проверить тип исключения

`assert` проверяет только истинность логического выражения. Он не умеет проверять, было ли возбуждено определённое исключение — для этого нужен `pytest.raises` или `unittest.assertRaises`.

---

## 💡 Важные нюансы

- `assert` — инструмент **отладки**, не обработки ошибок.
- Всегда должен быть побочным-эффект-свободным: не следует писать `assert list.append(x)` — операция может не выполниться, если assert отключён.
- Для валидации пользовательских данных и критичной бизнес-логики — только исключения, не assert.
