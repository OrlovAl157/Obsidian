# 🐍 pytest — основы

## 📌 Коротко

> `pytest` — сторонний фреймворк тестирования (`pip install pytest`), который упрощает и расширяет `unittest`: меньше шаблонного кода, обычный `assert` вместо десятков методов, более подробные и наглядные отчёты об ошибках. Тесты чаще пишутся функциями, а не методами класса.

---

## 🚀 Быстрая справка

| Требование | Правило |
|---|---|
| Имя функции-теста | префикс `test` |
| Имя файла с тестами | префикс `test_` или суффикс `_test` |
| Имя тестового класса | префикс `Test`, **без наследования** |
| Проверка | обычный `assert выражение` |
| Проверка исключения | `with pytest.raises(Тип): ...` |
| Запуск | команда `pytest` в терминале или `pytest.main()` |

---

## 📖 Основное

### Минимальный пример

```python
def test_factorial_one():
    assert factorial(1) == 1

def test_factorial_five():
    assert factorial(5) == 120
```

Никакого наследования от специального класса не нужно — pytest сам находит функции с префиксом `test`. При ошибке отчёт показывает не просто «не равно», а разворачивает выражение целиком:

```
E       assert 120 == 121
E        +  where 120 = factorial(5)
```

Похожие тесты можно объединять в класс — просто для группировки, без всякого наследования, имя класса обязано начинаться с `Test`:

```python
class TestFactorial:
    def test_factorial_one(self):
        assert factorial(1) == 1
```

### Проверка исключений

```python
def test_exception():
    with pytest.raises(ValueError):
        factorial(-1)

# проверка ещё и текста сообщения — через match (регулярное выражение)
def test_exception_message():
    with pytest.raises(ValueError, match=r'^Некорректный аргумент\.$'):
        factorial(-1)
```

### Фикстуры через @pytest.fixture

Функция-фикстура готовит и **возвращает** данные; тестовая функция получает их через параметр с тем же именем, что и у фикстуры:

```python
@pytest.fixture
def cat():
    return Cat('Кемаль')

def test_cat(cat):          # pytest сам найдёт и вызовет фикстуру cat()
    assert cat.name == 'Кемаль'
```

По умолчанию фикстура создаётся заново для каждого теста (`scope='function'`). Уровень можно расширить: `@pytest.fixture(scope='class')` — один объект на весь класс, `scope='module'` — на весь модуль.

### yield вместо return — освобождение ресурсов

В отличие от unittest, у pytest нет отдельного метода вроде `tearDown()` — вместо этого фикстура использует `yield`: код до `yield` — это подготовка, код после — освобождение ресурсов:

```python
@pytest.fixture
def cat():
    instance = Cat('Кемаль')
    yield instance           # эта часть — «setUp», возвращает объект тестам
    del instance             # эта часть — «tearDown», выполняется после теста
```

**Рекомендация:** для фикстур всегда использовать `yield`, а не `return`, даже если очистка сейчас не нужна — заложить возможность на будущее.

## 💡 Важные нюансы

- В pytest тесты редко оформляются классами — функциональный стиль лаконичнее и pytest-idiomatic.
- pytest умеет запускать и unittest-тесты, и doctest (`pytest --doctest-modules`) — не обязательно всё переписывать.
- Глобальные фикстуры, доступные во всём проекте, кладутся в файл `conftest.py` в корне — их не нужно импортировать, pytest подхватывает автоматически.
