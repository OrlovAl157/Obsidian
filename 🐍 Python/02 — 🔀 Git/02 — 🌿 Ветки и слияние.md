# 🌿 Git — Ветки и слияние — памятка

> Ветка — отдельная линия разработки. Как черновик: делаешь изменения не трогая основной код, а потом сливаешь. Ветки дёшевы в Git — создавай их часто.

## Справка

| Команда | Что делает |
|---|---|
| `git branch` | Показать все локальные ветки |
| `git branch <имя>` | Создать ветку |
| `git switch <ветка>` | Переключиться на ветку |
| `git switch -c <имя>` | Создать и переключиться |
| `git branch -d <имя>` | Удалить ветку (безопасно) |
| `git branch -D <имя>` | Удалить принудительно |
| `git merge <ветка>` | Слить ветку в текущую |
| `git rebase <ветка>` | Перенести коммиты на другую ветку |
| `git merge --abort` | Отменить слияние при конфликте |

## 📊 Общая схема

```
main:    A───B───C
                  \
feature:           D───E───F

После git merge feature:
main:    A───B───C───────M   (M = merge commit)
                  \     /
feature:           D───E───F

После git rebase main (из feature):
main:    A───B───C
                  \
feature:           D'──E'──F'  (коммиты перенесены, история линейная)
```

## 🌿 Работа с ветками

```bash
# Просмотр
git branch                   # локальные ветки
git branch -a                # все ветки включая remote
git branch -v                # ветки с последним коммитом

# Создание и переключение
git switch -c feature/login  # создать и переключиться ✅ современный способ
git checkout -b feature/login # то же самое, старый способ

# Переключение
git switch main              # переключиться на main
git checkout main            # то же самое, старый способ

# Удаление
git branch -d feature/login  # безопасно — только если ветка слита
git branch -D feature/login  # принудительно — даже если не слита ⚠️

# Переименование
git branch -m старое новое   # переименовать ветку
```

**Текущая ветка** помечена `*` в выводе `git branch`:

```
* main
  feature/login
  bugfix/sort
```

## 🔀 Слияние — merge

```bash
# Находясь на main, слить feature:
git switch main
git merge feature/login
```

**Fast-forward merge** — когда main не двигался пока ты работал в feature:

```
До:     main: A───B
              feature: A───B───C───D

После:  main: A───B───C───D   (просто двигает указатель, без merge commit)
```

**3-way merge** — когда оба branch двигались:

```
До:     main: A───B───C
              feature: A───B───D───E

После:  main: A───B───C───────M
                    \         /
                     D───E───/
```

**Конфликт при merge:**

```bash
git merge feature/login
# Auto-merging file.py
# CONFLICT (content): Merge conflict in file.py

# Файл с конфликтом выглядит так:
<<<<<<< HEAD
код из main
=======
код из feature
>>>>>>> feature/login

# Решаешь вручную → сохраняешь → добавляешь → коммитишь
git add file.py
git commit -m "Разрешил конфликт"

# Или отменяешь слияние:
git merge --abort
```

## ♻️ Перебазирование — rebase

```bash
# Находясь в feature, перебазировать на main:
git switch feature/login
git rebase main
```

Rebase переносит коммиты feature поверх актуального main — история становится линейной.

```bash
# Интерактивный rebase — можно сквошить, редактировать коммиты
git rebase -i HEAD~3    # последние 3 коммита

# pick   = оставить коммит
# squash = объединить с предыдущим
# reword = изменить сообщение
# drop   = удалить коммит
```

**Конфликт при rebase:**

```bash
# Если конфликт — решаешь, потом:
git add file.py
git rebase --continue   # продолжить rebase

# Или отменить:
git rebase --abort
```

## ⚡ merge vs rebase

| Аспект | `merge` | `rebase` |
|---|---|---|
| История | Сохраняет разветвление | Линейная, чистая |
| Merge commit | Создаёт | Не создаёт |
| Безопасность | Безопасен всегда | Опасен на shared ветках |
| Когда | Финальное слияние в main | Обновить feature от main |

```
merge:   A───B───C───M    история показывает что ветки были
rebase:  A───B───C───D'   история выглядит как будто всё линейно
```

> ⚠️ **Не делай rebase на shared ветках** (main, develop) — переписывает историю, создаёт проблемы у других разработчиков.

## 💡 Практические замечания

- Называй ветки понятно: `feature/login`, `bugfix/sort-error`, `hotfix/payment`
- `git switch` — современная замена `git checkout` для переключения веток (Git 2.23+)
- Перед слиянием убедись что находишься на принимающей ветке (`git branch`)
- После слияния удаляй ненужные ветки — `git branch -d`
- `git rebase main` из feature — безопасно и удобно для синхронизации

## ⚠️ Частые ошибки

**❌ Забыл переключиться на main перед merge:**
```bash
git merge feature/login    # ❌ если сейчас в feature — сольёт main в feature!
git switch main
git merge feature/login    # ✅
```

**❌ Rebase на shared ветке:**
```bash
git switch main
git rebase feature         # ❌ опасно — переписывает историю main!
git switch feature
git rebase main            # ✅ безопасно — переписываем только feature
```

**❌ Удалил ветку до слияния:**
```bash
git branch -d feature/login   # ❌ если не слита — Git предупредит
git branch -D feature/login   # ⚠️ принудительно — данные могут потеряться
```

## ✅ Главные правила

✅ Новая задача — новая ветка  
✅ `git switch -c <имя>` — создать и переключиться  
✅ Перед `merge` — убедись что ты на принимающей ветке  
✅ `merge` — для финального слияния в main  
✅ `rebase` — для обновления feature от main  
✅ Никогда не делай `rebase` на shared ветках  
✅ После слияния удаляй ветку — `git branch -d`
