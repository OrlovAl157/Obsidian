# 📋 Git — Основы, коммиты, история — памятка

> Git — система контроля версий. Сохраняет историю изменений кода, позволяет откатиться назад и работать в команде. Основа любого серьёзного проекта.

## Справка

| Команда | Что делает |
|---|---|
| `git init` | Создать репозиторий |
| `git clone <url>` | Скопировать с GitHub/GitLab |
| `git status` | Показать состояние файлов |
| `git add <файл>` | Добавить в staging |
| `git add .` | Добавить все изменения |
| `git commit -m "текст"` | Сохранить снимок |
| `git log --oneline` | Краткая история |
| `git diff` | Что изменилось (до staging) |
| `git diff --staged` | Что изменилось (после staging) |

## 📊 Общая схема

```
Рабочая директория      Staging area         Репозиторий
(Working Directory)     (Index)              (.git)
        │                    │                    │
  Редактируешь          git add →            git commit →
  файлы                 готовишь             сохраняешь
                        снимок               историю

Состояния файла:
  Untracked → Staged → Committed
      │           │         │
  новый файл   git add   git commit
  (Git не       добавил   сохранил
  знает о нём)  в очередь  навсегда

HEAD → указатель на последний коммит текущей ветки
```

## 🔧 Настройка

Выполняется **один раз** при установке Git:

```bash
git config --global user.name "Твоё Имя"
git config --global user.email "email@example.com"
git config --list        # проверить все настройки
git config user.name     # проверить конкретный параметр
```

**Важное:** имя и email попадают в каждый коммит — их видят все кто работает с репозиторием.

## 🆕 Создание репозитория

```bash
# Новый проект с нуля
git init                 # создаёт папку .git в текущей директории

# Скопировать существующий
git clone https://github.com/user/repo.git        # клонирует в папку repo
git clone https://github.com/user/repo.git mydir  # клонирует в папку mydir
```

После `git init`:
```
my_project/
├── .git/        ← вся история хранится здесь
├── main.py
└── README.md
```

## 🔍 Состояние файлов

```bash
git status               # полный статус
git status -s            # краткий статус

git diff                 # изменения НЕ добавленные в staging
git diff --staged        # изменения УЖЕ добавленные в staging
git diff HEAD            # все изменения с последнего коммита
```

**Краткий статус (`-s`):**

```
M  file.py    ← изменён и добавлен в staging
 M file2.py   ← изменён но НЕ добавлен в staging
?? new.py     ← новый файл (untracked)
A  added.py   ← новый файл добавлен в staging
```

## ➕ Add и Commit

> Аналогия: `add` — сложить вещи в коробку, `commit` — запечатать и подписать коробку.

```bash
# Add — добавить в staging
git add file.py          # один файл
git add .                # все изменения в текущей папке
git add *.py             # все .py файлы
git add -p               # интерактивно — выбрать части файла

# Commit — сохранить снимок
git commit -m "Добавил авторизацию"        # с сообщением
git commit -am "Исправил баг"              # add + commit (только tracked файлы)
git commit --amend -m "Новое сообщение"    # исправить последний коммит
```

**Хорошее сообщение коммита:**

```bash
# ❌ Плохо
git commit -m "fix"
git commit -m "changes"

# ✅ Хорошо
git commit -m "Добавил валидацию email при регистрации"
git commit -m "Исправил ошибку сортировки в списке пользователей"
```

## 📜 История

```bash
git log                          # полная история
git log --oneline                # одна строка на коммит
git log --oneline --graph        # дерево веток
git log --oneline -5             # последние 5 коммитов
git log --author="Имя"          # коммиты конкретного автора
git log file.py                  # история конкретного файла

git show <hash>                  # детали конкретного коммита
git show HEAD                    # детали последнего коммита
```

**Пример вывода `git log --oneline`:**

```
a3f2c1d Добавил авторизацию
9b8e4a2 Исправил баг сортировки
3d1f7b0 Начальный коммит
```

Первые 7 символов (`a3f2c1d`) — это **hash** коммита. Используется в командах отмены и навигации.

## 💡 Практические замечания

- `.gitignore` — файл со списком того что Git игнорирует (`__pycache__`, `.env`, `*.pyc`)
- `git add -p` — добавляет изменения по частям, удобно для аккуратных коммитов
- `git commit --amend` — исправить последний коммит (сообщение или файлы), но только если ещё не запушил
- `HEAD~1` — один коммит назад от HEAD, `HEAD~3` — три назад
- Коммит создаёт снимок всего проекта, не только изменённых файлов

## ⚠️ Частые ошибки

**❌ Забыл добавить файл в staging:**
```bash
git commit -m "Добавил фичу"   # ← файл не добавлен в staging, не войдёт в коммит
git add file.py
git commit -m "Добавил фичу"   # ✅
```

**❌ Сделал коммит с опечаткой в сообщении:**
```bash
git commit --amend -m "Правильное сообщение"  # ✅ только если не запушил
```

**❌ Добавил в коммит лишний файл:**
```bash
git restore --staged secret.env   # убрать из staging до коммита ✅
```

**❌ `git add .` добавил файлы которые не нужны:**
```bash
# Создай .gitignore и добавь туда маску:
__pycache__/
*.pyc
.env
.DS_Store
```

## ✅ Главные правила

✅ Настрой имя и email один раз — `git config --global`  
✅ `git status` перед каждым коммитом — проверяй что добавляешь  
✅ Коммиты маленькие и частые — легче читать историю  
✅ Сообщение коммита — конкретное и понятное  
✅ `git add .` — осторожно, добавляет всё; используй `.gitignore`  
✅ `HEAD` — всегда указывает на текущий коммит  
✅ Hash коммита — первые 7 символов из `git log --oneline`
