## 🧱 Основные понятия

**Назначение:** разделить четыре понятия, которые часто путают.

**Collection (коллекция)** — объект, который хранит набор значений одного или разных типов.

**Sequence (последовательность)** — коллекция, элементы которой идут в строгом порядке и имеют индексы. `set` и `dict` последовательностями не являются: у `set` нет порядка, а `dict` хранит порядок вставки (с Python 3.7), но обращение идёт по ключу, а не по позиции.

**Iterable (итерируемый объект)** — объект, на основе которого можно создать итератор (имеет `__iter__()`). Все коллекции итерируемые, и сам итератор тоже.

**Iterator (итератор)** — объект, который выдаёт следующее значение при применении `next()` и возбуждает `StopIteration`, когда значений больше нет.

**Примеры:**

```python
numbers = [1, 2, 3, 4]
print(numbers[2])               # → 3 (последовательность — доступ по индексу)

iterator = iter(numbers)
# print(iterator[1])            # → TypeError (у итератора индексов нет)
```

```python
my_list = [1, 2, 3]            # iterable
my_iter = iter(my_list)         # создали итератор
print(next(my_iter))            # → 1
print(next(my_iter))            # → 2
print(next(my_iter))            # → 3
# print(next(my_iter))          # → StopIteration
```

## 🗺 Иерархия и схема связей

**Назначение:** увидеть, кто чей частный случай.

```
Iterable                         ← можно создать итератор: iter(obj)
 ├── Collection                  ← хранит значения (есть len, in, перебор)
 │    ├── Sequence               ← порядок + индексы: list, tuple, str, range
 │    ├── set
 │    └── dict
 └── Iterator                    ← выдаёт по одному: next(obj)
      ├── list_iterator, set_iterator, tuple_iterator
      ├── map, filter, enumerate, zip
      └── generator
```

Поток работы с итератором:

```
iterable (list, tuple, str, ...)
      │  iter()
      ▼
   iterator
      │  next()  → элемент
      │  next()  → элемент
      │  next()  → StopIteration (элементы закончились)
```

**Важное:** стрелка идёт в **одну сторону**: из iterable делают итератор через `iter()`. Итератор — тоже iterable (`iter(it)` возвращает `it`), но обычный iterable итератором не является.

## 📐 Range — ленивая последовательность

**Назначение:** понять, почему `range` ведёт себя и как последовательность, и как «ленивый» объект, но итератором не является.

`range` — **неизменяемая последовательность**. Он не хранит все числа, а хранит только `start`, `stop`, `step` и вычисляет любой элемент по запросу. Поэтому он занимает мало памяти, но при этом поддерживает индексацию и срезы.

| Возможность | `range` | Итератор |
| --- | --- | --- |
| Индексация `r[i]` | ✅ | ❌ |
| Срезы `r[a:b]` (результат — `range`) | ✅ | ❌ |
| `len(r)` | ✅ | ❌ |
| Повторный перебор | ✅ | ❌ |
| `x in r` не опустошает | ✅ | ❌ |
| Можно как ключ словаря (неизменяем, хешируем) | ✅ | — |
| `next(r)` | ❌ `TypeError` | ✅ |

**Примеры:**

```python
r = range(1, 10, 2)                  # 1, 3, 5, 7, 9
print(r.start, r.stop, r.step)       # → 1 10 2
print(r[2], len(r), r[1:3])          # → 5 5 range(3, 7, 2)

print(list(r))                       # → [1, 3, 5, 7, 9]
print(list(r))                       # → [1, 3, 5, 7, 9] (многоразовый)

print(len(range(1000000000)))        # → 1000000000 (мгновенно, ничего не хранится)
print(999999999 in range(10**9))     # → True (проверка без перебора)

print({range(3): 'a'})               # → {range(0, 3): 'a'}
```

```python
# range — iterable, но не iterator
# next(range(3))                     # → TypeError: 'range' object is not an iterator
it = iter(range(3))                  # а вот итератор из него создаётся
print(type(it))                      # → <class 'range_iterator'>
print(next(it))                      # → 0
```

**Важное:** «ленивость» `range` — это вычисление элементов по формуле, а не движение итератора. Поэтому `range` не опустошается и его не назовёшь «чем-то средним между последовательностью и итератором»: это полноценная последовательность.

## 🔄 Многоразовый iterable

**Назначение:** сделать собственный класс, по которому можно ходить многократно.

Итератор одноразовый, потому что хранит позицию. Если нужен объект для многократного перебора (как список или `range`), класс должен быть **iterable**, а не итератором: его `__iter__()` каждый раз создаёт **новый** итератор.

**Вариант 1 — `__iter__()` как генератор (самый короткий):**

```python
class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        yield from range(self.start, 0, -1)   # каждый вызов — новый генератор

c = Countdown(3)
print(list(c))                  # → [3, 2, 1]
print(list(c))                  # → [3, 2, 1] (можно снова)
```

**Вариант 2 — отдельный класс-итератор:**

```python
class CountdownIterator:
    def __init__(self, current):
        self.current = current

    def __iter__(self):
        return self                      # итератор возвращает self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value

class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        return CountdownIterator(self.start)   # новый итератор при каждом вызове

c = Countdown(3)
print(list(c))                  # → [3, 2, 1]
print(list(c))                  # → [3, 2, 1]
```

Здесь возврат нового объекта из `__iter__()` корректен, потому что `Countdown` — **iterable**, а не итератор. Для **итератора** такой возврат ломает протокол (см. раздел «Зачем итератору возвращать self» в [[01 — Итераторы (Iterator)]]).

**Старый протокол через `__getitem__`.** Если у класса нет `__iter__()`, но есть `__getitem__()` с индексами от `0`, то `iter()` создаст итератор сам, а `IndexError` остановит перебор:

```python
class Squares:
    def __getitem__(self, i):
        if i >= 3:
            raise IndexError
        return i * i

print(list(Squares()))          # → [0, 1, 4]
```

## 🔬 Проверка типов через collections.abc

**Назначение:** надёжно проверять, с чем имеешь дело.

```python
from collections.abc import Iterable, Iterator, Sequence

print(isinstance([1, 2], Iterable))          # → True
print(isinstance([1, 2], Iterator))          # → False (список — не итератор)
print(isinstance(iter([1, 2]), Iterator))    # → True
print(isinstance(range(3), Sequence))        # → True
print(isinstance(range(3), Iterator))        # → False
print(isinstance({1: 2}, Sequence))          # → False
```

**Важное:** для проверок используй `collections.abc`, а не устаревшие алиасы из `typing`.

## ⚠️ Частые ошибки

**❌ ОШИБКА:** считать `range` итератором.

```python
# next(range(3))                 # → TypeError
```

✅ `range` — iterable (и последовательность). Итератор получают через `iter(range(3))`.

---

**❌ ОШИБКА:** считать `dict` и `set` последовательностями и обращаться по индексу.

```python
# {1, 2, 3}[0]                   # → TypeError
```

✅ Индексы есть только у последовательностей: `list`, `tuple`, `str`, `range`.

---

**❌ ОШИБКА:** делать класс, который одновременно iterable и итератор, и возвращать новый объект из `__iter__()`.

✅ Раздели роли: iterable создаёт новый итератор, итератор возвращает `self`.

---

**❌ ОШИБКА:** путать Collection и Iterable: у итератора и генератора нет `len()`, они не коллекции, но итерируемые.

## ✅ Главные правила

✅ Collection хранит значения, Sequence добавляет порядок и индексы  
✅ Iterable → `iter()` → Iterator → `next()` → `StopIteration`  
✅ Любой итератор — iterable, но обычный iterable — не итератор  
✅ `range` — ленивая неизменяемая последовательность, не итератор  
✅ Индексация и срезы — только у последовательностей  
✅ Нужен многоразовый перебор — делай iterable-класс с новым итератором в `__iter__()`  
✅ Для проверок типов — `collections.abc`
