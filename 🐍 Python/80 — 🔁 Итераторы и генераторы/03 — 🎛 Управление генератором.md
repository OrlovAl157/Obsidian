# 🎛 Управление генератором — памятка

> Генератор можно не только читать, но и управлять им: передавать значения (`send()`), закрывать (`close()`), возбуждать исключения (`throw()`), узнавать состояние и значение `return`. Раньше на этом строились сопрограммы, сейчас их заменили `async`/`await`.

## 📋 Справка

| Метод / функция | Что делает | Пример |
| --- | --- | --- |
| `next(gen)` | запускает генератор / берёт следующее значение | `next(gen)` |
| `gen.send(x)` | передаёт `x` в место `yield`, возвращает следующее значение | `gen.send(10)` |
| `gen.send(None)` | то же, что `next(gen)` | `gen.send(None)` |
| `gen.close()` | закрывает генератор на месте приостановки | `gen.close()` |
| `gen.throw(exc)` | возбуждает исключение на месте приостановки | `gen.throw(ValueError('...'))` |
| `getgeneratorstate(gen)` | возвращает состояние | `from inspect import getgeneratorstate` |

| Состояние | Значение |
| --- | --- |
| `GEN_CREATED` | только создан, ещё не начал выполняться |
| `GEN_RUNNING` | выполняется интерпретатором |
| `GEN_SUSPENDED` | приостановлен на `yield` |
| `GEN_CLOSED` | исчерпан или закрыт |

## 📨 Метод send()

**Назначение:** передать значение внутрь генератора в то место, где он приостановлен на `yield`.

Чтобы использовать полученное значение, `yield` нужно присвоить переменной: `value = yield`. Именно в ней окажется значение, переданное через `send()`.

**Примеры:**

```python
def print_value():
    print('Начало выполнения генератора')
    value = yield                    # получаем значение
    print(value)

generator = print_value()
next(generator)                      # → Начало выполнения генератора (инициализация)
generator.send(5)                    # → 5, затем StopIteration (больше нет yield)
```

`send()` не только передаёт значение, но и **возвращает** то, что генератор отдаст следующим `yield`. В примере выше следующего `yield` нет, поэтому итог — `StopIteration`. Добавим второй:

```python
def print_value():
    print('Начало выполнения генератора')
    value = yield
    print(value)
    yield 'Полученное значение выведено успешно'

generator = print_value()
next(generator)
print(generator.send(5))
# → Начало выполнения генератора
# → 5
# → Полученное значение выведено успешно
```

`yield` в одном выражении и отдаёт, и принимает. Значение после `yield` вернёт первый `next()`:

```python
def print_value():
    print('Начало выполнения генератора')
    value = yield 'Генератор приостановлен, ждём значение'
    print(value)
    yield 'Полученное значение выведено успешно'

generator = print_value()
print(next(generator))        # → Начало..., затем «Генератор приостановлен, ждём значение»
print(generator.send(5))      # → 5, затем «Полученное значение выведено успешно»
```

**Инициализация обязательна.** Перед первым `send()` с реальным значением генератор нужно дойти до первого `yield`:

```python
generator = print_value()
# generator.send(5)
# → TypeError: can't send non-None value to a just-started generator
```

**Пример — накопитель суммы:**

```python
def get_sum():
    total = 0
    while True:
        num = yield total        # отдаём сумму, получаем следующее число
        total += num

generator = get_sum()
print(next(generator))           # → 0 (инициализация)
print(generator.send(10))        # → 10  (0 + 10)
print(generator.send(40))        # → 50  (0 + 10 + 40)
print(generator.send(19))        # → 69  (0 + 10 + 40 + 19)
```

Что происходит при каждом `send(x)`: `x` попадает в `num`, прибавляется к `total`, цикл делает следующий виток и `yield total` отдаёт обновлённую сумму как результат `send()`.

Такой генератор бесконечен. Завершить его можно стоп-значением, которое станет условием выхода из цикла, либо методами `close()` и `throw()`.

## 🔒 Метод close()

**Назначение:** закрыть генератор там, где он приостановлен.

После `close()` любое обращение к генератору (`next()`, `send()`) возбуждает `StopIteration`.

```python
generator = get_sum()
next(generator)

generator.close()                # закрываем
# generator.send(10)             # → StopIteration
```

В точке приостановки внутри генератора возбуждается `GeneratorExit`, поэтому блоки `finally` выполняются:

```python
def gen():
    try:
        yield 1
        yield 2
    finally:
        print('Очистка')

g = gen()
next(g)
g.close()                        # → Очистка
```

**Важное:** на `GeneratorExit` нельзя отвечать новым `yield`, это даст `RuntimeError`.

## 💥 Метод throw()

**Назначение:** возбудить исключение внутри генератора на месте приостановки `yield`.

Принимает экземпляр исключения. Если генератор его **не** обрабатывает, исключение вылетает наружу:

```python
def get_sum():
    total = 0
    while True:
        num = yield total
        total += num

generator = get_sum()
next(generator)

for n in range(10):
    result = generator.send(n)
    if result > 10:
        generator.throw(ValueError('Превышен лимит суммы'))
    print(result)
# → 0, 1, 3, 6, 10, затем ValueError: Превышен лимит суммы
```

Если исключение **обработано** в генераторе, `throw()` вернёт следующее значение `yield`, как `send()`:

```python
def get_sum():
    total = 0
    while True:
        try:
            num = yield total
            total += num
        except ValueError:
            print('Сбрасываем сумму')
            total = 0

generator = get_sum()
next(generator)

for n in range(10):
    result = generator.send(n)
    if result > 10:
        result = generator.throw(ValueError('Превышен лимит суммы'))
    print(result)
# → 0, 1, 3, 6, 10, Сбрасываем сумму, 0, 6, Сбрасываем сумму, 0, 8, Сбрасываем сумму, 0
```

При превышении лимита исключение перехвачено, `total` обнулён, на следующем витке цикла `yield total` отдал `0`, и это значение стало результатом `throw()`.

## 📝 Нюансы send, throw и close

**1. Инициализация через `send(None)`.** `next(gen)` равнозначен `gen.send(None)`:

```python
generator = get_sum()
print(generator.send(None))      # → 0 (инициализация и первая сумма)
print(generator.send(10))        # → 10
print(generator.send(40))        # → 50
```

**2. `throw()` и `close()` работают без инициализации:**

```python
generator1 = get_sum()
generator2 = get_sum()

generator1.close()
try:
    next(generator1)
except StopIteration:
    print('Генератор закрыт')           # → Генератор закрыт

try:
    generator2.throw(ValueError('Превышен лимит суммы'))
except ValueError as err:
    print(err)                          # → Превышен лимит суммы
```

**3. `send()` работает и у генераторов с аргументами:**

```python
def get_sum(start):
    total = start
    while True:
        num = yield total
        total += num

generator = get_sum(5)
print(next(generator))           # → 5
print(generator.send(10))        # → 15
print(generator.send(40))        # → 55
print(generator.send(19))        # → 74
```

## 🚦 Состояния генератора

**Назначение:** узнать, в какой фазе жизни находится генератор.

Функция `getgeneratorstate()` из модуля `inspect` возвращает одно из четырёх состояний (см. таблицу в «Справке»).

```python
from inspect import getgeneratorstate

generator = get_sum()
print(getgeneratorstate(generator))     # → GEN_CREATED

next(generator)
print(getgeneratorstate(generator))     # → GEN_SUSPENDED

generator.close()
print(getgeneratorstate(generator))     # → GEN_CLOSED
```

`GEN_RUNNING` можно увидеть только изнутри самого генератора, пока он выполняется:

```python
def get_sum():
    total = 0
    while True:
        print(getgeneratorstate(generator))   # → GEN_RUNNING
        num = yield total
        total += num

generator = get_sum()
print(next(generator))           # → GEN_RUNNING, затем 0
print(generator.send(10))        # → GEN_RUNNING, затем 10
```

## 🏁 return и StopIteration

**Назначение:** вернуть из генератора итоговое значение.

`return value` в генераторе завершает его и кладёт `value` в атрибут `StopIteration.value`. Цикл `for` этого значения не видит, достать его можно вручную:

```python
def gen():
    yield 1
    return 'готово'

g = gen()
next(g)
try:
    next(g)
except StopIteration as e:
    print(e.value)               # → готово
```

`yield from` забирает это значение сам:

```python
def sub():
    yield 1
    return 'готово'

def main():
    result = yield from sub()    # result = 'готово'
    print(result)
    yield 2

print(list(main()))              # → готово, затем [1, 2]
```

## 🛡 StopIteration внутри генератора

**Назначение:** не потерять ошибку из-за автоматической замены исключения (PEP 479).

С Python 3.7 `StopIteration`, возникшее **внутри** генератора, превращается в `RuntimeError`. Иначе оно молча завершило бы генератор, и ошибка осталась бы незамеченной.

```python
def bad():
    yield 1
    raise StopIteration          # ❌

# list(bad())                    # → RuntimeError: generator raised StopIteration
```

✅ Для завершения генератора используй `return`.

Так же ведёт себя «чужой» `next()` внутри генератора, который выбрасывает `StopIteration` у исчерпанного итератора. Безопаснее `next(it, default)`.

## ⚠️ Частые ошибки

**❌ ОШИБКА:** `send()` с реальным значением до первого `next()`.

```python
# generator.send(5)
# → TypeError: can't send non-None value to a just-started generator
```

✅ Сначала `next(generator)` или `generator.send(None)`.

---

**❌ ОШИБКА:** обращаться к генератору после `close()`.

```python
generator.close()
# generator.send(10)             # → StopIteration
```

---

**❌ ОШИБКА:** писать `raise StopIteration` внутри генератора → `RuntimeError`. Используй `return`.

**❌ ОШИБКА:** `yield` в ответ на `GeneratorExit` (внутри `close()`) → `RuntimeError`.

**⚠️ Ловушка:** `throw()` без обработчика исключение не гасит, оно вылетает наружу и закрывает генератор.

---

## ✅ Главные правила

✅ `send(x)` передаёт значение в `value = yield` и возвращает следующее значение генератора  
✅ Перед первым `send(x)` нужна инициализация: `next(gen)` или `send(None)`  
✅ `close()` закрывает генератор, дальше будет `StopIteration`  
✅ `throw(exc)` возбуждает исключение на месте `yield`; если его обработать, вернётся следующее значение  
✅ `throw()` и `close()` можно вызывать до инициализации  
✅ Состояние смотрит `inspect.getgeneratorstate()`  
✅ `return value` → `StopIteration.value`; `yield from` отдаёт это значение вызывающему  
✅ Внутри генератора не поднимай `StopIteration`, пиши `return`  
✅ `send`, `throw`, `close` раньше управляли сопрограммами на генераторах, с `async`/`await` напрямую они нужны редко
