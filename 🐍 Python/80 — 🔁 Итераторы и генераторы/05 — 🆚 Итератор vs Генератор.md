# 🆚 Итератор vs Генератор — памятка

> Генератор — подтип итератора и удобный способ его создать через `yield` или `( ... for ...)`. Итератор — это протокол (`__iter__` + `__next__`), генератор — одна из его реализаций, к которой добавлены `send()`, `throw()` и `close()`.

## 📋 Справка

| Характеристика | Итератор | Генератор |
| --- | --- | --- |
| Что это | протокол (интерфейс) | конкретная реализация итератора |
| Создание | класс с `__iter__` и `__next__` | функция с `yield` или выражение `( ... )` |
| Объём кода | ~15–20 строк на класс | ~5 строк |
| Оператор `yield` | нет | есть в функции-генераторе (в выражении его нет) |
| Передача данных внутрь | не предусмотрена протоколом | `send()` |
| Дополнительные методы | только `__iter__`, `__next__` | + `send()`, `throw()`, `close()` |
| Отношение | базовое | подтип итератора |

## 🔬 Доказательство кодом

**Назначение:** показать, что генератор — подтип итератора, но не наоборот.

```python
from collections.abc import Iterator, Generator

gen_  = (i for i in range(5))     # генератор
iter_ = iter(range(5))            # итератор

print(gen_)                       # → <generator object <genexpr> at 0x...>
print(iter_)                      # → <range_iterator object at 0x...>

print(isinstance(gen_, Iterator))     # → True  (генератор — итератор)
print(isinstance(iter_, Generator))   # → False (итератор — не генератор)
```

## 🤝 Что у них общего

**Назначение:** запомнить, что по поведению генератор — обычный итератор.

```python
from itertools import tee

gen_ = (i for i in range(5))

print(gen_ is iter(gen_))          # → True (iter() возвращает сам объект)
print(next(gen_))                  # → 0 (next() работает)

a, b = tee(gen_)                   # tee принимает и генератор
print(list(a), list(b))            # → [1, 2, 3, 4] [1, 2, 3, 4]

gen2 = (i for i in range(3))
print(list(gen2))                  # → [0, 1, 2]
print(list(gen2))                  # → [] (одноразовый, как любой итератор)
```

## 🌟 Что есть только у генератора

**Назначение:** главное отличие — генератор можно приостанавливать и управлять им.

```python
def echo():
    value = None
    while True:
        value = yield value        # получаем данные извне

gen = echo()
next(gen)                          # инициализация

print(gen.send('Hello'))           # → Hello
print(gen.send('World'))           # → World
```

- `yield` — приостановка с сохранением состояния
- `send()` — передача данных внутрь, `throw()` — исключение внутрь, `close()` — закрытие
- до `async`/`await` на этом строились сопрограммы (корутины) на генераторах

**Важное:** свой класс-итератор тоже может определить метод `send()`, но протокол итератора этого не требует, а у генератора эти методы есть всегда. Подробнее — в [[03 — 🎛 Управление генератором]].

**Объём кода** (задача одна — диапазон чисел):

```python
class Counter:                          # итератор-класс
    def __init__(self, low, high):
        self.current = low
        self.high = high

    def __iter__(self):
        return self

    def __next__(self):
        if self.current > self.high:
            raise StopIteration
        self.current += 1
        return self.current - 1

def counter(low, high):                 # генератор
    while low <= high:
        yield low
        low += 1

print(list(Counter(1, 5)))              # → [1, 2, 3, 4, 5]
print(list(counter(1, 5)))              # → [1, 2, 3, 4, 5]
```

## 💬 Разбор ответов из сообщества

**Назначение:** вопрос «чем генератор отличается от итератора» часто задают на собеседованиях джунов. В обсуждениях встречаются разные ответы, вот их суть и оценка.

| № | Ответ (суть) | Оценка |
| --- | --- | --- |
| 1 | Итератор — механизм поэлементного обхода, генератор — отложенное создание результата; генератор — подтип итератора, но не наоборот | ✅ верно |
| 2 | Контраргумент: итератор тоже ленив, а у генератора те же свойства (исчерпывается, `iter(gen) is gen`, работает `next()`) | ✅ верно: ленивость отличием не является |
| 3 | Итерируемый объект и итератор — протоколы; генератор — не протокол, а конкретный механизм реализации | ✅ верно |
| 4 | Итератор — универсальный интерфейс, генераторная функция — конкретная реализация («`range()` — генератор целых, `enumerate()` — генератор кортежей») | ⚠️ суть верна, примеры нет: `range` — ленивая последовательность (iterable, не итератор), `enumerate` — итератор-класс, не генератор |
| 5 | «Разница в наличии `yield`, всё» | ⚠️ упрощение: генераторное выражение — генератор без `yield`; не учтены `send`/`throw`/`close` |
| 6 | Документация: генераторы — удобный способ реализовать протокол итератора | ✅ верно |
| 7 | Глоссарий: generator — функция, возвращающая generator iterator; PEP 342 добавил приём данных (`send`, `throw`, `close`) и корутины до `async`/`await` | ✅ верно, ключевое отличие здесь |
| 8 | Генератор — подтип/наследник итератора («отец и сын»), расширяет его возможности; удобный синтаксис, управление из коробки, почти полная совместимость с итераторами | ✅ верно по сути; «метакласс» в рассказе про старые итераторы лишний: раньше писали обычные классы |

## 🎤 Ответы на собеседовании

**Простой:**

> Генератор — это удобный способ создания итераторов с помощью функции и `yield`.

**Технический:**

> Генератор — подтип итератора. Итератор — это протокол, генератор — конкретная реализация этого протокола.

**С деталями:**

> Генератор является итератором, но с дополнительными возможностями: `yield` приостанавливает выполнение, а методы `send()`, `throw()` и `close()` позволяют передавать в него данные, исключения и закрывать его. Создаётся функцией с `yield` или генераторным выражением.

**Чего лучше не говорить:** «вопрос некорректен, это как сравнивать автомобиль и зубную щётку». Генератор — не другая сущность, а подвид итератора, сравнение вполне осмысленное.

## ⚠️ Частые заблуждения

**❌ ОШИБКА:** «Генератор — это не итератор».

✅ Каждый генератор является итератором (`isinstance(gen, Iterator)` → `True`).

---

**❌ ОШИБКА:** «Без `yield` генератора не бывает».

✅ Генераторное выражение `(i for i in ...)` — генератор без `yield`.

---

**❌ ОШИБКА:** «`range` и `enumerate` — генераторы».

✅ `range` — iterable и последовательность, `enumerate` — итератор. Генераторами они не являются.

---

**❌ ОШИБКА:** «Любой итератор можно перебрать дважды, а генератор нельзя».

✅ Одноразовы оба.

---

## ✅ Главные правила

✅ Генератор ЯВЛЯЕТСЯ итератором, итератор не обязан быть генератором  
✅ Итератор — протокол, генератор — удобная реализация  
✅ Главное отличие — `yield` (приостановка с сохранением состояния) и методы `send()`, `throw()`, `close()`  
✅ Генераторное выражение — тоже генератор, хотя `yield` в нём нет  
✅ Ленивость и одноразовость — общие свойства, а не отличие  
✅ Для проверки типов используй `collections.abc.Iterator` и `Generator`
