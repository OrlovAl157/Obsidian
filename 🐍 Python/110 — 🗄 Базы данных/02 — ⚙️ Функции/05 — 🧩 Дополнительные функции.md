## 🔍 Работа с NULL

**Назначение:** проверять `NULL`, подставлять значения по умолчанию и выбирать первое непустое значение.

| Функция | Синтаксис | Что важно помнить |
| --- | --- | --- |
| `ISNULL` | `ISNULL(expr)` | Проверяет, является ли значение `NULL`. |
| `COALESCE` | `COALESCE(a, b, ...)` | Возвращает первое не-`NULL` значение. |
| `IFNULL` | `IFNULL(expr1, expr2)` | Если первое значение `NULL`, возвращает второе. |
| `NULLIF` | `NULLIF(a, b)` | Если значения равны, возвращает `NULL`. |

**Примеры:**

```sql
SELECT ISNULL(NULL);
-- 1

SELECT ISNULL('value');
-- 0

SELECT COALESCE(NULL, NULL, 2, 3);
-- 2

SELECT IFNULL(NULL, 'geek');
-- geek

SELECT NULLIF('bee', 'bee');
-- NULL

SELECT NULLIF('bee', 'geek');
-- bee
```

**Важное:** `COALESCE()` особенно полезна, когда нужно перебрать сразу несколько возможных источников значения. Работает быстрее вложенных `IFNULL()`.




## ❓ Условные функции

**Назначение:** возвращать разные результаты в зависимости от условия.

| Функция | Синтаксис | Что важно помнить |
| --- | --- | --- |
| `IF` | `IF(cond, a, b)` | Возвращает одно из двух значений по условию. |

**Примеры:**

```sql
SELECT IF(1 < 0, 'bee', 'geek');
-- geek

SELECT IF(age >= 18, 'adult', 'minor');
-- разные результаты в зависимости от возраста

SELECT IF(salary IS NULL, 0, salary);
-- подставить 0 если зарплата не указана
```

**Важное:** `IF()` удобна для коротких условий, когда не нужен полный `CASE`. Для множества условий используй `CASE`.




## 🔄 Приведение типов

**Назначение:** явно преобразовывать значение к нужному типу данных. Полезно когда база хранит числа как строки или нужна точность при округлении.

| Функция | Синтаксис | Что важно помнить |
| --- | --- | --- |
| `CONVERT` | `CONVERT(expr, type)` | Стиль MySQL, также умеет менять кодировку. |
| `CAST` | `CAST(expr AS type)` | Стандарт SQL, предпочтительнее для переносимости. |

**Доступные типы:**

| Тип | Что означает | Пример |
|---|---|---|
| `SIGNED` | Целое со знаком (может быть отрицательным) | `-100`, `0`, `42` |
| `UNSIGNED` | Целое без знака (только ≥ 0) | `0`, `42`, `999` |
| `DECIMAL(p, s)` | Число с фиксированной точностью `p` знаков, `s` после точки | `DECIMAL(5, 2)` → `123.45` |
| `FLOAT` | Число с плавающей точкой | `3.14` |
| `CHAR` | Строка фиксированной длины | `'hello'` |
| `CHAR(n)` | Строка длиной n символов | `CHAR(10)` |
| `DATE` | Дата `YYYY-MM-DD` | `2025-05-05` |
| `DATETIME` | Дата и время `YYYY-MM-DD HH:MM:SS` | `2025-05-05 14:30:00` |
| `TIME` | Время `HH:MM:SS` | `14:30:00` |
| `JSON` | JSON объект | `{"key": "value"}` |

**Примеры:**

```sql
-- DECIMAL — число с заданной точностью
SELECT CAST(100.78 AS DECIMAL(5, 1));   -- → 100.8  (5 знаков всего, 1 после точки)
SELECT CAST(100.78 AS DECIMAL(3, 0));   -- → 101    (без дробной части, округление)
SELECT CONVERT(100.78, DECIMAL(4, 1));  -- → 100.8  (то же самое через CONVERT)

-- SIGNED / UNSIGNED — целые числа
SELECT CAST('123' AS SIGNED);           -- → 123    (строка → целое со знаком)
SELECT CAST('-42' AS SIGNED);           -- → -42
SELECT CAST('99' AS UNSIGNED);          -- → 99     (строка → целое без знака)
SELECT CAST(-1 AS UNSIGNED);            -- → очень большое число ⚠️ осторожно!
SELECT CONVERT('123', SIGNED);          -- → 123    (то же через CONVERT)

-- DATE / DATETIME / TIME
SELECT CAST('2023-10-20' AS DATE);      -- → 2023-10-20
SELECT CAST('2023-10-20 14:30' AS DATETIME); -- → 2023-10-20 14:30:00
SELECT CAST('14:30:00' AS TIME);        -- → 14:30:00

-- CHAR — число в строку
SELECT CAST(42 AS CHAR);                -- → '42'
SELECT CAST(3.14 AS CHAR);             -- → '3.14'

-- Некорректное преобразование — не ошибка, а 0 или NULL!
SELECT CAST('abc' AS SIGNED);          -- → 0  ⚠️ не ошибка!
SELECT CAST('12abc' AS SIGNED);        -- → 12 ⚠️ берёт только числовую часть!
```

**CAST vs CONVERT:**

```sql
-- CAST — стандарт SQL, работает везде
CAST(expr AS type)

-- CONVERT — MySQL синтаксис, плюс умеет менять кодировку
CONVERT(expr, type)
CONVERT(expr USING utf8mb4)   -- смена кодировки — только CONVERT умеет это!
```

**Важное:**
- `CAST('abc' AS SIGNED)` возвращает `0`, а не ошибку — будь осторожен при работе с ненадёжными данными
- `CAST(-1 AS UNSIGNED)` даст очень большое число — MySQL интерпретирует битовый паттерн
- `CAST()` предпочтительнее `CONVERT()` если нужна переносимость на другие СУБД
- Для смены кодировки строки — только `CONVERT(expr USING charset)`




## 📋 Конструкция CASE

**Назначение:** описать несколько условий и выбрать результат по одному из них.

| Вариант | Синтаксис | Что важно помнить |
| --- | --- | --- |
| `CASE expr` | `CASE expr WHEN ... THEN ... END` | Удобен, когда сравнивается одно выражение с разными значениями. |
| `CASE` | `CASE WHEN cond THEN ... END` | Удобен для произвольных логических условий. |

**Примеры:**

Вариант 1: сравнение с выражением

```sql
SELECT
    product_name,
    CASE quantity
        WHEN 0 THEN 'Out of stock'
        WHEN 1 THEN 'One in stock'
        WHEN 2 THEN 'Little in stock'
        WHEN 3 THEN 'Little in stock'
        WHEN 4 THEN 'Little in stock'
        WHEN 5 THEN 'Little in stock'
        ELSE 'A lot in stock'
    END AS availability
FROM products;
```

Вариант 2: логические условия

```sql
SELECT
    product_name,
    CASE
        WHEN quantity = 0 THEN 'Out of stock'
        WHEN quantity = 1 THEN 'One in stock'
        WHEN quantity BETWEEN 2 AND 5 THEN 'Little in stock'
        ELSE 'A lot in stock'
    END AS availability
FROM products;
```

Результат выполнения

```text
+--------------------+
| availability       |
+--------------------+
| A lot in stock     |
| One in stock       |
| Little in stock    |
| Little in stock    |
| Out of stock       |
+--------------------+
```

**Важное:** `CASE` удобнее `IF()`, когда условий больше двух или когда логика должна оставаться читаемой. `CASE` может быть в SELECT, WHERE, ORDER BY и даже в GROUP BY.

## 💡 Практические замечания

- Для обработки `NULL` в выводе используй `COALESCE()` вместо вложенных `IFNULL()` — это читаемее и быстрее.
- `CASE WHEN` работает в индексах и часто оптимизируется лучше, чем `IF()` на больших выборках.
- При приведении типов помни о потере точности: `CAST('abc' AS INT)` вернёт 0, не ошибку.
- `IF()` вычисляет оба варианта — для сложных вычислений лучше использовать `CASE`.
- Используй `NULLIF()` для избежания ошибок деления на ноль: `a / NULLIF(b, 0)`.
- `CAST()` более портативна, чем `CONVERT()` — используй её если планируешь переносить запрос на другие СУБД.
- В больших таблицах `CASE` часто работает быстрее `IF()` благодаря лучшей оптимизации.
