# 👁 Представления (VIEW) — памятка

> Представление — виртуальная таблица основанная на SELECT-запросе. Данные не хранятся физически — при обращении к представлению выполняется его запрос. Упрощает сложные запросы, обеспечивает безопасность, скрывает детали структуры.

## Справка

| Команда | Что делает |
|---|---|
| `CREATE VIEW v AS SELECT ...` | создать представление |
| `CREATE OR REPLACE VIEW v AS SELECT ...` | создать или заменить |
| `ALTER VIEW v AS SELECT ...` | изменить представление |
| `DROP VIEW v` | удалить представление |
| `DROP VIEW IF EXISTS v` | удалить если существует |
| `SHOW FULL TABLES WHERE Table_type = 'VIEW'` | показать все представления |
| `SHOW CREATE VIEW v` | показать код представления |
| `CREATE VIEW v AS SELECT ... WITH CHECK OPTION` | защита от несогласованных данных |

## 📊 Общая схема

```
Реальная таблица Books:
+----+------------------------+-----------+-------+--------+
| id | title                  | author_id | price | amount |
+----+------------------------+-----------+-------+--------+

Представление ExpensiveBooks:
CREATE VIEW ExpensiveBooks AS
SELECT id, title, price FROM Books WHERE price > 10;

Обращение к представлению:
SELECT * FROM ExpensiveBooks;
↑ MySQL выполняет: SELECT id, title, price FROM Books WHERE price > 10

Представление — не копия данных! Это сохранённый запрос.
При каждом обращении данные берутся из реальных таблиц.
```

## 🟢 Создание и использование

```sql
-- Простое представление
CREATE VIEW ExpensiveBooks AS
SELECT id, title, author_id, price
FROM Books
WHERE price > 10;

-- С JOIN
CREATE VIEW BooksWithAuthors AS
SELECT b.id, b.title, a.author, b.price, b.amount
FROM Books b
INNER JOIN Authors a ON b.author_id = a.id;

-- Использование — как обычная таблица
SELECT * FROM BooksWithAuthors;
SELECT * FROM BooksWithAuthors WHERE author = 'Stephen King';
SELECT * FROM BooksWithAuthors ORDER BY price DESC LIMIT 5;

-- Представление в JOIN
SELECT b.title, b.price, o.quantity
FROM BooksWithAuthors b
JOIN Orders o ON b.id = o.book_id;

-- Представление с псевдонимами полей
CREATE VIEW BookStats AS
SELECT
    author_id,
    COUNT(*) AS book_count,
    AVG(price) AS avg_price,
    SUM(amount) AS total_amount
FROM Books
GROUP BY author_id;

SELECT * FROM BookStats;
-- | author_id | book_count | avg_price | total_amount |
-- | 1         | 2          | 11.99     | 7            |
-- | 2         | 2          | 11.99     | 20           |
```

## 🔵 Изменение и удаление

```sql
-- Изменить существующее представление
ALTER VIEW ExpensiveBooks AS
SELECT id, title, author_id, price
FROM Books
WHERE price > 15;   -- изменили условие

-- CREATE OR REPLACE — создать если нет, заменить если есть
CREATE OR REPLACE VIEW ExpensiveBooks AS
SELECT id, title, author_id, price
FROM Books
WHERE price > 20;

-- Удалить представление
DROP VIEW ExpensiveBooks;

-- Удалить если существует (без ошибки если нет)
DROP VIEW IF EXISTS ExpensiveBooks;

-- Удалить несколько представлений
DROP VIEW IF EXISTS ExpensiveBooks, BooksWithAuthors, BookStats;

-- Просмотр всех представлений
SHOW FULL TABLES WHERE Table_type = 'VIEW';

-- Просмотр кода представления
SHOW CREATE VIEW BooksWithAuthors;
```

## 🔴 Обновляемые представления

Через представление можно вставлять, обновлять и удалять данные если оно удовлетворяет условиям:

```sql
-- Простое представление — обновляемое
CREATE VIEW CheapBooks AS
SELECT id, title, price
FROM Books
WHERE price < 10;

-- INSERT через представление
INSERT INTO CheapBooks (id, title, price)
VALUES (10, 'New Book', 5.99);
-- Запись добавится в реальную таблицу Books!

-- UPDATE через представление
UPDATE CheapBooks
SET price = 4.99
WHERE id = 10;
-- Обновится реальная таблица Books

-- DELETE через представление
DELETE FROM CheapBooks WHERE id = 10;
-- Удалится из реальной таблицы Books
```

**Условия обновляемости** — представление НЕ обновляемо если содержит:

| Ограничение | Пример |
|---|---|
| `DISTINCT` | `SELECT DISTINCT author FROM Books` |
| Агрегатные функции | `COUNT()`, `SUM()`, `AVG()`, `MAX()`, `MIN()` |
| `GROUP BY` или `HAVING` | `GROUP BY author_id` |
| `UNION` или `UNION ALL` | несколько SELECT |
| Подзапрос в WHERE | `WHERE price = (SELECT MIN...)` |
| Несколько таблиц (JOIN) | в большинстве случаев |

## 🟡 WITH CHECK OPTION

Защищает от вставки/обновления данных которые не попадают под условие представления:

```sql
-- Без WITH CHECK OPTION — можно добавить запись которой нет в представлении
CREATE VIEW CheapBooks AS
SELECT id, title, price FROM Books WHERE price < 10;

INSERT INTO CheapBooks VALUES (10, 'Expensive Book', 99.99);
-- Вставится в Books! Но в CheapBooks не будет видна — это неожиданно

-- С WITH CHECK OPTION — защита от несогласованных данных
CREATE VIEW CheapBooks AS
SELECT id, title, price FROM Books
WHERE price < 10
WITH CHECK OPTION;

INSERT INTO CheapBooks VALUES (10, 'Expensive Book', 99.99);
-- ERROR 1369: CHECK OPTION failed — price = 99.99 не удовлетворяет WHERE price < 10

UPDATE CheapBooks SET price = 15.99 WHERE id = 1;
-- ERROR 1369: CHECK OPTION failed — после обновления запись выйдет из представления
```

**LOCAL vs CASCADED:**

```sql
-- WITH LOCAL CHECK OPTION — проверяет только условие этого представления
CREATE VIEW v1 AS SELECT * FROM Books WHERE price < 10
WITH LOCAL CHECK OPTION;

-- WITH CASCADED CHECK OPTION — проверяет условия всех вложенных представлений
CREATE VIEW v2 AS SELECT * FROM v1 WHERE amount > 0
WITH CASCADED CHECK OPTION;   -- проверит и WHERE price < 10 и WHERE amount > 0
```

## 🟣 Когда использовать

**✅ Упрощение сложных запросов:**

```sql
-- Без представления — копируешь JOIN везде
SELECT b.title, a.author, b.price
FROM Books b
JOIN Authors a ON b.author_id = a.id
WHERE b.price > 10;

-- С представлением — один раз создал, везде используешь
CREATE VIEW PremiumBooks AS
SELECT b.title, a.author, b.price
FROM Books b
JOIN Authors a ON b.author_id = a.id
WHERE b.price > 10;

SELECT * FROM PremiumBooks;   -- просто!
```

**✅ Безопасность — скрыть чувствительные данные:**

```sql
-- Таблица users содержит password, credit_card и т.д.
CREATE VIEW PublicUsers AS
SELECT id, name, email   -- только безопасные поля
FROM users;

-- Выдать доступ только к представлению, не к таблице
GRANT SELECT ON PublicUsers TO 'webapp_user';
```

**✅ Логическая независимость — скрыть изменения структуры:**

```sql
-- Изменили структуру таблицы: разбили поле name на first_name + last_name
-- Обновляем только представление, приложение не замечает изменений
CREATE OR REPLACE VIEW UsersCompat AS
SELECT id, CONCAT(first_name, ' ', last_name) AS name, email
FROM users;
```

## ⚡ Быстрые примеры

```sql
-- Создать
CREATE VIEW ActiveBooks AS
SELECT * FROM Books WHERE amount > 0;

-- С JOIN
CREATE VIEW BooksWithAuthors AS
SELECT b.title, a.author, b.price
FROM Books b
JOIN Authors a ON b.author_id = a.id;

-- С агрегацией
CREATE VIEW AuthorStats AS
SELECT author_id, COUNT(*) AS cnt, AVG(price) AS avg_price
FROM Books
GROUP BY author_id;

-- CREATE OR REPLACE
CREATE OR REPLACE VIEW ActiveBooks AS
SELECT * FROM Books WHERE amount > 5;

-- Изменить
ALTER VIEW ActiveBooks AS
SELECT id, title, price FROM Books WHERE amount > 0;

-- Удалить
DROP VIEW IF EXISTS ActiveBooks;

-- WITH CHECK OPTION
CREATE VIEW CheapBooks AS
SELECT * FROM Books WHERE price < 10
WITH CHECK OPTION;

-- Использовать
SELECT * FROM BooksWithAuthors WHERE author = 'King';
SELECT COUNT(*) FROM ActiveBooks;
UPDATE ActiveBooks SET price = 9.99 WHERE id = 1;
```

## 💡 Практические замечания

- Представление — сохранённый запрос, данные не дублируются
- При изменении данных в таблице — представление автоматически отражает изменения
- `CREATE OR REPLACE` удобнее чем `DROP + CREATE` — не нужно пересоздавать права
- Представления с `GROUP BY`, `JOIN`, агрегатами — не обновляемые
- `WITH CHECK OPTION` — всегда используй для обновляемых представлений с `WHERE`
- Злоупотребление представлениями может замедлить запросы — это не кэш!

## ⚠️ Частые ошибки

**❌ Думаешь что представление кэширует данные:**
```sql
-- Представление НЕ хранит данные — каждый раз выполняет запрос
SELECT * FROM HeavyView;   -- если запрос тяжёлый — будет медленно каждый раз
-- Для кэша используй временные таблицы или материализованные представления
```

**❌ Обновляешь необновляемое представление:**
```sql
CREATE VIEW AuthorStats AS
SELECT author_id, COUNT(*) AS cnt FROM Books GROUP BY author_id;

UPDATE AuthorStats SET cnt = 10 WHERE author_id = 1;
-- ERROR 1288: The target table AuthorStats is not updatable
```

**❌ Вставка без WITH CHECK OPTION — данные вне условия:**
```sql
CREATE VIEW CheapBooks AS SELECT * FROM Books WHERE price < 10;

INSERT INTO CheapBooks VALUES (99, 'Expensive', 'Author', 99.99);
-- Вставится в Books но не будет видна в CheapBooks — сюрприз!
-- Используй WITH CHECK OPTION!
```

**❌ DROP TABLE вместо DROP VIEW:**
```sql
DROP TABLE CheapBooks;   -- ❌ пытается удалить таблицу!
DROP VIEW CheapBooks;    -- ✅ удаляет представление
```

---

## ✅ Главные правила

✅ Представление — сохранённый запрос, не копия данных  
✅ `CREATE OR REPLACE VIEW` — обновить без пересоздания прав  
✅ Обновляемое представление — без `DISTINCT`, `GROUP BY`, агрегатов, `UNION`, `JOIN`  
✅ `WITH CHECK OPTION` — защита от вставки данных вне условия  
✅ `DROP VIEW IF EXISTS` — удалить без ошибки если не существует  
✅ Изменения в таблице — автоматически видны через представление  
✅ Для безопасности — выдавай доступ к представлению, не к таблице  
✅ Представление не ускоряет тяжёлые запросы — это не кэш
