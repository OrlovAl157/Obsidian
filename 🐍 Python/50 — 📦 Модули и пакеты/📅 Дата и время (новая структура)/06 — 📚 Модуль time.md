# 📚 Модуль time — памятка

> Модуль `time` — не путать с типом `time` из `datetime` (см. [[02 — ⏰ time (тип)]])! Этот модуль про низкоуровневую работу со временем: паузы в выполнении кода, замер производительности, Unix timestamp. Меньше про "человеческие" даты, больше — про системное время.

## 🟢 time.time — Unix timestamp

```python
import time

time.time()   # 1704063599.123456 — секунд с 1970-01-01 00:00:00 UTC
```

## 🟠 time.ctime — читаемая строка

Секунды с начала эпохи неудобны для человека — `ctime()` превращает их в читаемую строку локального времени:

```python
import time

time.ctime(1630387918.354396)   # 'Tue Aug 31 08:31:58 2021'

# Без аргумента — использует time.time() автоматически
time.ctime()                    # текущее локальное время строкой
```

Результат зависит от географического положения (часового пояса) компьютера, на котором выполняется код, но не учитывает языковую локаль (в отличие от `strftime()`) — названия дня и месяца всегда на английском.

---

## 🔵 time.sleep — пауза

Приостанавливает выполнение программы на заданное количество секунд:

```python
import time

time.sleep(2)      # пауза на 2 секунды
time.sleep(0.5)    # пауза на 0.5 секунды — дробные значения работают
```

Частое применение — искусственная задержка между повторными запросами к API (retry-логика), имитация долгой операции при тестировании.

## 🔴 Замер времени выполнения

```python
import time

# time.time() — годится для грубой оценки, подвержен переводу системных часов
start = time.time()
# ... код ...
end = time.time()
print(f"Время выполнения: {end - start} сек")

# time.perf_counter() — точнее, для коротких интервалов и бенчмарков
start = time.perf_counter()
# ... код ...
end = time.perf_counter()
print(f"Время: {end - start} сек")
```

**Почему `perf_counter()` лучше для замеров:** `time.time()` берёт значение из системных часов, которые могут быть скорректированы (например, синхронизацией NTP) прямо во время замера, что исказит результат. `perf_counter()` использует монотонный счётчик, который никогда не идёт назад — надёжнее для измерения "сколько реально прошло времени".

## 🟡 struct_time и форматирование

Модуль `time` использует свою структуру `struct_time` — более старый, "сишный" способ представления даты/времени (до появления удобного `datetime`):

```python
import time

t = time.localtime()    # текущее локальное время как struct_time
t.tm_year                # год
t.tm_mon                 # месяц
t.tm_mday                # день
t.tm_hour, t.tm_min, t.tm_sec

# Форматирование — коды те же %Y %m %d, что и в datetime, см. [[05 — 📝 Форматирование]]
time.strftime('%d.%m.%Y %H:%M:%S', time.localtime())

# Парсинг строки в struct_time
time.strptime('31.12.2024', '%d.%m.%Y')
```

**На практике** для дат обычно удобнее `datetime`, а модуль `time` используют точечно — для `sleep()` и `perf_counter()`. `struct_time` встречается редко, в основном в legacy-коде или при работе с низкоуровневыми системными вызовами.
