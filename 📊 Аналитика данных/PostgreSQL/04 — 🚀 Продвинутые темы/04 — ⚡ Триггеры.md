# ⚡ Триггеры — памятка

> Триггер — функция, автоматически выполняемая при INSERT/UPDATE/DELETE. В PostgreSQL триггер это отдельная функция, возвращающая `TRIGGER`, плюс привязка `CREATE TRIGGER`. Нет `DELIMITER` — используют `$$`.

## Справка

| Синтаксис | Что делает |
|---|---|
| `CREATE FUNCTION ... RETURNS TRIGGER` | функция-триггер |
| `CREATE TRIGGER ... BEFORE INSERT` | до вставки |
| `CREATE TRIGGER ... AFTER UPDATE` | после обновления |
| `FOR EACH ROW` | для каждой строки |
| `FOR EACH STATEMENT` | для всего запроса |
| `NEW` | новые значения (INSERT/UPDATE) |
| `OLD` | старые значения (UPDATE/DELETE) |
| `DROP TRIGGER name ON table` | удалить триггер |

## 🟢 Создание триггера

В PostgreSQL триггер создаётся в два шага:
1. Создать функцию, возвращающую `TRIGGER`
2. Создать триггер, вызывающий эту функцию

```sql
-- Шаг 1: функция-триггер
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;   -- обязательно для BEFORE триггера!
END;
$$ LANGUAGE plpgsql;

-- Шаг 2: привязка триггера
CREATE TRIGGER trigger_updated_at
BEFORE UPDATE ON Books
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

**Нет `DELIMITER`!** В PostgreSQL используют `$$` как разделитель тела функции — это просто строковый литерал, не специальный синтаксис.

## 🔵 NEW и OLD

| Триггер | NEW | OLD |
|---|---|---|
| BEFORE INSERT | ✅ можно менять | ❌ нет |
| AFTER INSERT | ✅ только читать | ❌ нет |
| BEFORE UPDATE | ✅ можно менять | ✅ только читать |
| AFTER UPDATE | ✅ только читать | ✅ только читать |
| BEFORE DELETE | ❌ нет | ✅ только читать |
| AFTER DELETE | ❌ нет | ✅ только читать |

```sql
CREATE OR REPLACE FUNCTION log_price_change()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.price != NEW.price THEN
        INSERT INTO PriceLog (book_id, old_price, new_price)
        VALUES (NEW.id, OLD.price, NEW.price);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## 🔴 Порядок выполнения INSERT

```
INSERT INTO table (...)
        │
        ▼
1. Черновик NEW в памяти (ограничения не проверяются)
        │
        ▼
2. BEFORE INSERT триггер — может менять NEW
        │
        ▼
3. Проверка ограничений (NOT NULL, UNIQUE, FK...)
        │
        ▼
4. Строка записывается в таблицу
        │
        ▼
5. AFTER INSERT триггер — строка уже в таблице, NEW нельзя менять
```

**BEFORE** — работает с черновиком NEW до записи в таблицу.
**AFTER** — строка уже в таблице, изменить через NEW нельзя.

## 🟣 Практические примеры

```sql
-- 1. Автоматически заполнять created_at и updated_at
CREATE OR REPLACE FUNCTION set_timestamps()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        NEW.created_at = NOW();
    END IF;
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. Нормализация имени при вставке
CREATE OR REPLACE FUNCTION normalize_name()
RETURNS TRIGGER AS $$
BEGIN
    NEW.name = INITCAP(TRIM(NEW.name));
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 3. Удаление триггера
DROP TRIGGER trigger_updated_at ON Books;
```

## ✅ Главные правила

✅ PostgreSQL: сначала функция `RETURNS TRIGGER`, потом `CREATE TRIGGER`  
✅ `RETURN NEW` — обязательно в BEFORE-триггере (иначе операция отменится)  
✅ `RETURN NULL` в BEFORE-триггере — отменить операцию  
✅ Нет `DELIMITER` — используй `$$` как разделитель тела  
✅ `TG_OP` — 'INSERT', 'UPDATE' или 'DELETE' — тип операции
