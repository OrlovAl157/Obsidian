# 🚀 Индексы — памятка

> Индекс ускоряет поиск данных, но замедляет INSERT/UPDATE/DELETE. В PostgreSQL несколько типов индексов: B-Tree (по умолчанию), Hash, GIN, GiST, BRIN. Выбор типа зависит от задачи.

## Справка

| Синтаксис | Что делает |
|---|---|
| `CREATE INDEX idx ON t(col)` | B-Tree индекс |
| `CREATE UNIQUE INDEX` | уникальный индекс |
| `CREATE INDEX ... USING GIN` | GIN индекс |
| `CREATE INDEX ... WHERE condition` | частичный индекс |
| `DROP INDEX idx` | удалить индекс |
| `\di` | список индексов (psql) |
| `EXPLAIN ANALYZE SELECT ...` | план запроса |

---

## 🟢 Создание и удаление

```sql
-- Обычный B-Tree индекс
CREATE INDEX idx_books_author ON Books(author);
CREATE INDEX idx_books_price ON Books(price DESC);

-- Составной индекс
CREATE INDEX idx_books_author_price ON Books(author, price);

-- Уникальный индекс
CREATE UNIQUE INDEX idx_users_email ON Users(email);

-- Если не существует
CREATE INDEX IF NOT EXISTS idx_books_author ON Books(author);

-- Удаление
DROP INDEX idx_books_author;
DROP INDEX IF EXISTS idx_books_author;
```

---

## 🔵 Типы индексов

| Тип | Когда использовать |
|---|---|
| `B-Tree` | по умолчанию, `=`, `<`, `>`, `BETWEEN`, `LIKE 'abc%'` |
| `Hash` | только `=`, быстрее B-Tree для точного совпадения |
| `GIN` | JSONB, массивы, полнотекстовый поиск |
| `GiST` | геометрия, полнотекстовый поиск, диапазоны |
| `BRIN` | очень большие таблицы с физически упорядоченными данными |

```sql
CREATE INDEX idx_meta ON Users USING GIN (meta);           -- JSONB
CREATE INDEX idx_tags ON Articles USING GIN (tags);        -- массив
CREATE INDEX idx_search ON Books USING GIN (to_tsvector('english', title));
```

## 🔴 Специальные индексы

```sql
-- Частичный индекс — только часть строк
CREATE INDEX idx_active_users ON Users(email) WHERE is_active = TRUE;

-- Функциональный индекс
CREATE INDEX idx_lower_email ON Users(LOWER(email));
-- Тогда запрос WHERE LOWER(email) = 'a@b.com' использует индекс

-- Индекс на JSONB-поле
CREATE INDEX idx_city ON Users((meta->>'city'));

-- CONCURRENTLY — создание без блокировки таблицы
CREATE INDEX CONCURRENTLY idx_books_price ON Books(price);
```

## 🟣 EXPLAIN ANALYZE

```sql
-- Посмотреть план запроса
EXPLAIN SELECT * FROM Books WHERE author = 'King';

-- С реальной статистикой выполнения
EXPLAIN ANALYZE SELECT * FROM Books WHERE author = 'King';

-- Проверить использует ли индекс
-- Seq Scan — полный перебор (нет индекса или не используется)
-- Index Scan — используется индекс
-- Index Only Scan — данные из индекса, таблица не читается
```

## ✅ Главные правила

✅ B-Tree — по умолчанию для большинства задач  
✅ GIN — для JSONB, массивов, полнотекстового поиска  
✅ Частичный индекс — если часто запрашиваешь подмножество строк  
✅ `CREATE CONCURRENTLY` — создание без блокировки (для продакшна)  
✅ `EXPLAIN ANALYZE` — всегда проверяй, используется ли индекс  
✅ Не создавай индексы на маленьких таблицах и редко запрашиваемых полях
