# ⚡ Триггеры — памятка

> Триггер — хранимая процедура которая автоматически выполняется при `INSERT`, `UPDATE` или `DELETE`. Работает без явного вызова — срабатывает до или после операции над таблицей.

**Триггер всегда привязан к конкретной таблице и не может существовать отдельно от неё.** Если удалить таблицу — автоматически удалится и все привязанные к ней триггеры.

## Справка

| Синтаксис | Что делает |
|---|---|
| `CREATE TRIGGER name BEFORE INSERT ON t FOR EACH ROW ...` | триггер до вставки |
| `CREATE TRIGGER name AFTER UPDATE ON t FOR EACH ROW ...` | триггер после обновления |
| `DROP TRIGGER name` | удалить триггер |
| `DROP TRIGGER IF EXISTS name` | удалить если существует |
| `SHOW TRIGGERS` | показать все триггеры |
| `SHOW TRIGGERS FROM db` | триггеры конкретной БД |
| `NEW.col` | новое значение поля (INSERT, UPDATE) |
| `OLD.col` | старое значение поля (UPDATE, DELETE) |

| Тип | NEW | OLD | Можно изменять NEW |
|---|---|---|---|
| `BEFORE INSERT` | ✅ | ❌ | ✅ |
| `AFTER INSERT` | ✅ | ❌ | ❌ |
| `BEFORE UPDATE` | ✅ | ✅ | ✅ |
| `AFTER UPDATE` | ✅ | ✅ | ❌ |
| `BEFORE DELETE` | ❌ | ✅ | — |
| `AFTER DELETE` | ❌ | ✅ | — |

## 📊 Общая схема

```
Операция INSERT/UPDATE/DELETE
         │
    BEFORE триггер    ← можно изменить NEW, отменить операцию через SIGNAL
         │
    Сама операция
         │
    AFTER триггер     ← данные уже в таблице, можно логировать
         │
    Результат

Когда использовать BEFORE:
├── Валидация данных перед вставкой
├── Автозаполнение полей (created_at, updated_at)
└── Нормализация данных

Когда использовать AFTER:
├── Логирование изменений в другую таблицу
├── Обновление счётчиков/агрегатов
└── Уведомления и побочные эффекты
```

## 🟢 Создание триггера

**Зачем нужен DELIMITER:** по умолчанию разделителем запросов служит `;`. Тело триггера тоже содержит `;` после каждого оператора — СУБД воспримет первый же `;` внутри `BEGIN...END` как конец всего `CREATE TRIGGER` и оборвёт создание на середине. Чтобы этого не произошло, временно меняем разделитель на `//` — тогда СУБД понимает, что `;` внутри тела — это часть кода, а не конец запроса. После создания триггера возвращаем `;` обратно.

**Синтаксис с DELIMITER (рекомендуется):**

```sql
DELIMITER //

CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
    -- тело триггера
    -- может содержать несколько операторов
END //

DELIMITER ;
```

**Упрощённый синтаксис (один оператор):**

```sql
CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
SET NEW.updated_at = NOW();   -- один оператор без BEGIN/END
```

**`FOR EACH ROW` означает, что триггер выполняется отдельно для каждой затронутой записи.** Например, если один `INSERT` добавляет сразу 3 записи — триггер сработает 3 раза, по разу на каждую добавляемую строку, а не один раз на весь запрос.

## 🔵 NEW и OLD — доступ к данным

```sql
-- NEW — новые значения (при INSERT и UPDATE)
-- OLD — старые значения (при UPDATE и DELETE)

-- BEFORE UPDATE: оба доступны, NEW можно изменить
DELIMITER //
CREATE TRIGGER before_update_example
BEFORE UPDATE ON Products
FOR EACH ROW
BEGIN
    -- Смотрим старое значение
    IF OLD.price != NEW.price THEN
        SET NEW.price_updated_at = NOW();
    END IF;

    -- Изменяем новое значение до записи
    IF NEW.price < 0 THEN
        SET NEW.price = 0;
    END IF;
END //
DELIMITER ;

-- AFTER DELETE: только OLD
DELIMITER //
CREATE TRIGGER after_delete_log
AFTER DELETE ON Products
FOR EACH ROW
INSERT INTO DeletedProducts (id, name, price, deleted_at)
VALUES (OLD.id, OLD.name, OLD.price, NOW());
DELIMITER ;
```

## 🔴 Типы триггеров

**BEFORE INSERT — до вставки:**

```sql
-- Автоматически заполнить created_at
DELIMITER //
CREATE TRIGGER set_created_at
BEFORE INSERT ON users
FOR EACH ROW
SET NEW.created_at = NOW();
DELIMITER ;
```

**BEFORE UPDATE — до обновления:**

```sql
-- Проверить корректность данных + обновить метку
DELIMITER //
CREATE TRIGGER check_price
BEFORE UPDATE ON products
FOR EACH ROW
BEGIN
    IF NEW.price < 0 THEN
        SET NEW.price = 0;
    END IF;
    SET NEW.updated_at = NOW();
END //
DELIMITER ;
```

**AFTER INSERT — после вставки:**

```sql
-- Обновить счётчик в другой таблице
DELIMITER //
CREATE TRIGGER after_order_insert
AFTER INSERT ON Orders
FOR EACH ROW
UPDATE Customers
SET order_count = order_count + 1
WHERE id = NEW.customer_id;
DELIMITER ;
```

**AFTER UPDATE — после обновления:**

```sql
-- Логировать изменения цены
DELIMITER //
CREATE TRIGGER log_price_change
AFTER UPDATE ON Products
FOR EACH ROW
BEGIN
    IF OLD.price != NEW.price THEN
        INSERT INTO PriceHistory (product_id, old_price, new_price, changed_at)
        VALUES (OLD.id, OLD.price, NEW.price, NOW());
    END IF;
END //
DELIMITER ;
```

**BEFORE DELETE — до удаления:**

```sql
-- Запретить удаление товаров с активными заказами
DELIMITER //
CREATE TRIGGER prevent_delete_with_orders
BEFORE DELETE ON Products
FOR EACH ROW
BEGIN
    DECLARE order_count INT;
    SELECT COUNT(*) INTO order_count
    FROM Orders WHERE product_id = OLD.id AND status = 'active';

    IF order_count > 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Нельзя удалить товар с активными заказами';
    END IF;
END //
DELIMITER ;
```

**AFTER DELETE — после удаления:**

```sql
-- Архивировать удалённую запись
DELIMITER //
CREATE TRIGGER archive_deleted_user
AFTER DELETE ON Users
FOR EACH ROW
INSERT INTO UsersArchive (id, name, email, deleted_at)
VALUES (OLD.id, OLD.name, OLD.email, NOW());
DELIMITER ;
```

## 🟡 Управление триггерами

```sql
-- Просмотреть все триггеры
SHOW TRIGGERS;

-- Триггеры конкретной таблицы
SHOW TRIGGERS FROM database_name LIKE 'table_name';

-- Просмотреть код триггера
SHOW CREATE TRIGGER trigger_name;

-- Удалить триггер
DROP TRIGGER trigger_name;

-- Удалить если существует
DROP TRIGGER IF EXISTS trigger_name;
```

## 🔄 Порядок выполнения INSERT с триггером

```
INSERT INTO users (email) VALUES ('a@mail.com')
        │
        ▼
1. Формируется черновик NEW в памяти
   ┌──────────┬───────────────┐
   │ name     │ NULL          │  ← не передали — пока NULL
   │ email    │ 'a@mail.com'  │  ← передали
   │ created  │ NULL          │  ← не передали — пока NULL
   └──────────┴───────────────┘
   MySQL ещё не смотрит на ограничения —
   черновик просто отражает то, что пришло в INSERT
        │
        ▼
2. BEFORE INSERT триггер (если есть)
   ├── работает с черновиком NEW — строки в таблице ещё нет
   ├── может читать и менять любые поля NEW
   ├── ограничения ещё НЕ проверяются
   └── SET NEW.name = 'default'    ← заполнили дырку
       SET NEW.created = NOW()     ← заполнили дырку
   ┌──────────┬───────────────┐
   │ name     │ 'default'     │  ← уже не NULL
   │ email    │ 'a@mail.com'  │
   │ created  │ '2026-08-20'  │  ← уже не NULL
   └──────────┴───────────────┘
        │
        ▼
3. Проверка ограничений таблицы
   (NOT NULL, UNIQUE, CHECK, FOREIGN KEY...)
   ├── ✅ прошло → идём дальше
   └── ❌ ошибка → INSERT отменяется целиком
        │
        ▼
4. Строка записывается в таблицу  ← вот здесь строка впервые попадает в таблицу
        │
        ▼
5. AFTER INSERT триггер (если есть)
   ├── строка уже в таблице — работает с реальными данными
   └── изменить NEW уже нельзя
```

**BEFORE** — работает с черновиком `NEW` до записи в таблицу, строки ещё нет.  
**AFTER** — строка уже в таблице, изменить её через `NEW` нельзя.

**Как менять данные внутри триггера:**

- **Своя таблица** — просто `SET NEW.поле = значение`, не нужен UPDATE — триггер уже знает, с какой строкой работает:

```sql
IF NEW.price < 0 THEN
    SET NEW.price = 0;   -- меняем прямо через NEW
END IF;
```

- **Другая таблица** — нужен полноценный SQL-запрос:

```sql
-- триггер на Orders, обновляем счётчик в Users
UPDATE Users
SET order_count = order_count + 1
WHERE id = NEW.user_id;
```

**Автоматический `updated_at`:**

```sql
DELIMITER //
CREATE TRIGGER set_updated_at
BEFORE UPDATE ON Books
FOR EACH ROW
SET NEW.updated_at = NOW();
DELIMITER ;
```

**Запрет отрицательного остатка:**

```sql
DELIMITER //
CREATE TRIGGER check_stock
BEFORE UPDATE ON Products
FOR EACH ROW
BEGIN
    IF NEW.stock < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Остаток товара не может быть отрицательным';
    END IF;
END //
DELIMITER ;
```

**Каскадный счётчик:**

```sql
DELIMITER //
CREATE TRIGGER inc_book_count
AFTER INSERT ON Books
FOR EACH ROW
UPDATE Authors
SET book_count = book_count + 1
WHERE id = NEW.author_id;

CREATE TRIGGER dec_book_count
AFTER DELETE ON Books
FOR EACH ROW
UPDATE Authors
SET book_count = book_count - 1
WHERE id = OLD.author_id;
DELIMITER ;
```

## ⚡ Быстрые примеры

```sql
-- Автозаполнение created_at
CREATE TRIGGER set_created
BEFORE INSERT ON t FOR EACH ROW
SET NEW.created_at = NOW();

-- Запрет отрицательной цены
CREATE TRIGGER no_negative_price
BEFORE UPDATE ON products FOR EACH ROW
BEGIN
    IF NEW.price < 0 THEN SET NEW.price = 0; END IF;
END;

-- Логирование в другую таблицу
CREATE TRIGGER log_changes
AFTER UPDATE ON products FOR EACH ROW
INSERT INTO log (pid, old_p, new_p, ts) VALUES (OLD.id, OLD.price, NEW.price, NOW());

-- Архив при удалении
CREATE TRIGGER archive_row
AFTER DELETE ON users FOR EACH ROW
INSERT INTO users_archive SELECT OLD.*;

-- Запрет удаления через SIGNAL
CREATE TRIGGER prevent_delete
BEFORE DELETE ON critical_table FOR EACH ROW
SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Удаление запрещено';
```

## 💡 Практические замечания

- Триггер не может вызвать саму себя — нет рекурсии
- Триггер нельзя вызвать напрямую — только через DML операцию
- `BEFORE` триггер может изменить `NEW` — `AFTER` не может
- `SIGNAL SQLSTATE '45000'` — вызвать пользовательскую ошибку и отменить операцию
- На одну таблицу можно создать несколько триггеров одного типа (MySQL 5.7+)
- Триггер не выполняется при `TRUNCATE TABLE` — только при `DELETE`
- Если то же самое можно реализовать через `CHECK` или `FOREIGN KEY` — предпочтительнее ограничения: они, как правило, обрабатываются быстрее триггеров

## ⚠️ Частые ошибки

**❌ Изменение NEW в AFTER триггере:**
```sql
CREATE TRIGGER bad
AFTER INSERT ON t FOR EACH ROW
SET NEW.field = 'value';  -- ❌ данные уже записаны, изменить нельзя
-- Используй BEFORE INSERT для изменения данных
```

**❌ Доступ к NEW в DELETE триггере:**
```sql
CREATE TRIGGER bad_delete
BEFORE DELETE ON t FOR EACH ROW
SELECT NEW.id;  -- ❌ при DELETE нет NEW — только OLD
```

**❌ Бесконечная рекурсия:**
```sql
CREATE TRIGGER bad_loop
AFTER UPDATE ON t FOR EACH ROW
UPDATE t SET field = NEW.field;  -- ❌ обновляет ту же таблицу → рекурсия!
-- MySQL защитит от прямой рекурсии, но косвенная возможна
```

**❌ Забыл DELIMITER при многострочном триггере:**
```sql
CREATE TRIGGER bad
BEFORE INSERT ON t FOR EACH ROW
BEGIN
    SET NEW.x = 1;
END;  -- ❌ без DELIMITER ; прерывает CREATE TRIGGER!

DELIMITER //
CREATE TRIGGER good
BEFORE INSERT ON t FOR EACH ROW
BEGIN
    SET NEW.x = 1;
END //
DELIMITER ;  -- ✅
```

## ✅ Главные правила

✅ `BEFORE` — изменить данные до записи, валидация  
✅ `AFTER` — логирование, обновление счётчиков после записи  
✅ `NEW` — новые значения (INSERT, UPDATE), `OLD` — старые (UPDATE, DELETE)  
✅ `NEW` можно изменить только в `BEFORE` триггере  
✅ `SIGNAL SQLSTATE '45000'` — отменить операцию с ошибкой  
✅ При многострочном теле — обязательно `DELIMITER //`  
✅ `TRUNCATE` не вызывает `DELETE` триггеры  
✅ `SHOW TRIGGERS` — просмотреть все триггеры
