# 🧰 Диагностические команды — навигация, метаданные и состояние сервера

## Справка

| Команда | Что показывает |
| --- | --- |
| `SHOW DATABASES` | Список всех баз на сервере |
| `USE db` | Переключиться на базу (контекст для следующих запросов) |
| `SELECT DATABASE()` | Какая база активна сейчас |
| `SHOW TABLES` | Таблицы в текущей базе |
| `SHOW COLUMNS FROM table` | Колонки таблицы (как `DESCRIBE`, но с `LIKE`) |
| `DESCRIBE table` (`DESC table`) | Колонки: тип, `NULL`/`NOT NULL`, ключи, default |
| `SHOW CREATE TABLE table` | Полный `CREATE TABLE` (индексы, `FOREIGN KEY`) |
| `SHOW CREATE DATABASE db` | Команда создания базы (кодировка, collation) |
| `SHOW INDEX FROM table` | Все индексы таблицы |
| `SHOW TABLE STATUS` | Размер, движок, примерное число строк |
| `SHOW TRIGGERS` | Триггеры текущей базы |
| `SHOW PROCEDURE STATUS` | Хранимые процедуры |
| `SHOW FUNCTION STATUS` | Пользовательские функции |
| `SHOW PROCESSLIST` | Активные подключения и запросы |
| `KILL id` | Принудительно остановить запрос/подключение |
| `SELECT VERSION()` | Версия MySQL |
| `SHOW STATUS` | Статистика сервера (запросы, соединения, кэш) |
| `SHOW VARIABLES LIKE '...'` | Текущие настройки сервера |
| `SHOW WARNINGS` | Предупреждения последнего запроса |
| `SHOW ERRORS` | Ошибки последнего запроса |
| `SHOW ENGINE INNODB STATUS` | Внутреннее состояние InnoDB, включая последний deadlock |
| `ANALYZE TABLE table` | Пересчитывает статистику для оптимизатора |

## 🗂 Навигация по базам и таблицам

**Какие базы есть на сервере:**
```sql
SHOW DATABASES;
-- Database
-- information_schema
-- library
-- mysql
-- sakila
```

**Переключиться на конкретную базу** — после `USE` все запросы без явного указания базы выполняются в её контексте:
```sql
USE library;
```

**Какая база активна прямо сейчас:**
```sql
SELECT DATABASE();
-- → library
-- → NULL, если USE ещё не вызывался
```

**Таблицы в текущей базе:**
```sql
SHOW TABLES;
-- Tables_in_library
-- Authors
-- Books
-- Users
```

**Колонки таблицы с фильтром** — то же, что `DESCRIBE`, но можно искать по шаблону:
```sql
SHOW COLUMNS FROM Books LIKE '%price%';
-- Field | Type         | Null | Key | Default | Extra
-- price | decimal(6,2) | YES  |     | NULL    |
```

## 🧱 Структура объектов

```sql
DESCRIBE Books;
-- Field  | Type         | Null | Key | Default | Extra
-- id     | int          | NO   | PRI | NULL    | auto_increment
-- title  | varchar(255) | YES  |     | NULL    |
-- author | varchar(255) | YES  | MUL | NULL    |
-- price  | decimal(6,2) | YES  |     | NULL    |
```

Быстрый способ узнать структуру таблицы, не открывая `CREATE TABLE` целиком. `MUL` в `Key` — колонка участвует в обычном (не уникальном) индексе.

**Полная структура таблицы (с индексами и ограничениями):**
```sql
SHOW CREATE TABLE Books;
-- выдаёт CREATE TABLE целиком, которым можно пересоздать таблицу
```

**Команда создания базы** — полезно посмотреть кодировку и collation:
```sql
SHOW CREATE DATABASE library;
-- CREATE DATABASE library /*!40100 DEFAULT CHARACTER SET utf8mb4 */
```

**Все индексы таблицы** (быстрее, чем искать их по `SHOW CREATE TABLE`):
```sql
SHOW INDEX FROM Books;
```

**Размер и движок таблицы:**
```sql
SHOW TABLE STATUS LIKE 'Books';
-- Name  | Engine | Rows | Data_length | Index_length
-- Books | InnoDB | 5    | 16384       | 32768
```

`Rows` здесь — **оценка**, как и `rows` в `EXPLAIN`, может отличаться от реального числа при устаревшей статистике.

## 📜 Хранимые объекты

Узнать, какие триггеры, процедуры и функции вообще есть в базе, не вспоминая их имена наизусть.

```sql
SHOW TRIGGERS;
-- Trigger | Event  | Table | Statement | Timing
```

```sql
SHOW PROCEDURE STATUS WHERE Db = 'library';
-- Db | Name       | Type      | Definer
-- -- | ADD_ORDER  | PROCEDURE | root@localhost
```

```sql
SHOW FUNCTION STATUS WHERE Db = 'library';
```

> 💡 Текст самой процедуры/функции/триггера — через `SHOW CREATE PROCEDURE имя`, `SHOW CREATE FUNCTION имя`, `SHOW CREATE TRIGGER имя`.

Подробнее о процедурах и триггерах — [[06 — 📜 Процедуры]].

## 🖥 Состояние сервера

**Что сейчас выполняется на сервере** — полезно искать «зависший» запрос:
```sql
SHOW PROCESSLIST;
-- Id | User | Host | db | Command | Time | State | Info
```

**Остановить конкретный запрос/подключение** по его `Id` из `SHOW PROCESSLIST`:
```sql
KILL 42;
```

> ⚠️ `KILL` обрывает соединение. Если в нём была открытая транзакция без `COMMIT`, она автоматически откатится — см. [[03 — 🔄 Транзакции в MySQL]].

**Версия сервера:**
```sql
SELECT VERSION();
-- → 8.0.35
```

**Настройки сервера**, например уровень изоляции транзакций:
```sql
SHOW VARIABLES LIKE '%isolation%';
-- аналог: SELECT @@transaction_isolation;
```

**Статистика работы сервера** (счётчики запросов, соединений, кэша):
```sql
SHOW STATUS LIKE 'Threads_connected';
```

## 🧯 Диагностика проблем

**Предупреждения последнего запроса** — например, неявное приведение типов или усечение строки:
```sql
UPDATE Books SET price = 'abc' WHERE id = 1;
SHOW WARNINGS;
-- Level | Code | Message
-- Warning | 1366 | Incorrect decimal value: 'abc' for column 'price'
```

Также полезно сразу после `EXPLAIN` — показывает переписанный (оптимизированный) вариант запроса. Подробнее — [[07 — 📈 EXPLAIN и анализ запросов]].

**Ошибки последнего запроса** (аналогично `SHOW WARNINGS`, но для ошибок):
```sql
SHOW ERRORS;
```

**Внутреннее состояние InnoDB** — блокировки, транзакции, последний deadlock:
```sql
SHOW ENGINE INNODB STATUS;
-- Раздел LATEST DETECTED DEADLOCK — кто с кем столкнулся и какую транзакцию откатили
```

Используется для разбора ошибок вида `ERROR 1213: Deadlock found` — см. [[04 — 🧪 Параллельные транзакции — примеры]].

## 🔄 ANALYZE TABLE — обновление статистики

```sql
ANALYZE TABLE Orders;
```

Пересчитывает внутреннюю статистику таблицы (число строк, разнообразие значений в колонках) — именно её использует оптимизатор, решая между индексом и full table scan.

> 💡 Запускать после массовых изменений данных (удаление/вставка большого числа строк) — устаревшая статистика может привести к неоптимальному плану в `EXPLAIN` (например, `type = ALL` там, где индекс был бы выгоднее).

## 💡 Практические замечания

- `DESCRIBE` перед именем таблицы — структура; `DESCRIBE` перед `SELECT` — синоним `EXPLAIN`
- `SHOW CREATE TABLE` надёжнее для копирования структуры, чем `DESCRIBE` — включает индексы и внешние ключи
- Расхождение прогноза и факта в `EXPLAIN ANALYZE` — сигнал запустить `ANALYZE TABLE`
- Большинство `SHOW ...` команд принимают `LIKE 'шаблон'` для фильтрации по имени
- Эти команды не относятся к функциям/операторам SQL — это отдельные top-level команды интроспекции
- Многие `SHOW` есть и как `SELECT` из `information_schema` (например, `SELECT * FROM information_schema.TABLES`) — `SHOW` проще для разовой проверки, `information_schema` — когда нужна фильтрация или сортировка

## ⚠️ Частые ошибки

**❌ Пытаться выполнить запрос без `USE` и без указания базы:**
```sql
SELECT * FROM Books;
-- ❌ ERROR 1046: No database selected
```
✅ Сначала `USE library;`, либо указывать базу явно: `SELECT * FROM library.Books;`

**❌ Доверять `Rows` из `SHOW TABLE STATUS` как точному числу.** Это оценка, как и `rows` в `EXPLAIN` — для точного количества нужен `SELECT COUNT(*)`.

**❌ `KILL` соединения с открытой транзакцией без понимания последствий.** Незафиксированные изменения откатятся автоматически.

## ✅ Главные правила

✅ `SHOW DATABASES` → `USE db` → `SHOW TABLES` — стандартный порядок первого знакомства с сервером  
✅ `DESCRIBE` / `SHOW COLUMNS` — структура таблицы; `SHOW CREATE TABLE` — полная структура с индексами  
✅ `SHOW TRIGGERS` / `SHOW PROCEDURE STATUS` / `SHOW FUNCTION STATUS` — что хранится в базе, кроме таблиц  
✅ `SHOW PROCESSLIST` + `KILL id` — найти и остановить зависший запрос  
✅ `SHOW WARNINGS` / `SHOW ERRORS` — сразу после запроса, который вызывает подозрение  
✅ `SHOW ENGINE INNODB STATUS` — для разбора deadlock  
✅ Устаревшая статистика → `ANALYZE TABLE`
